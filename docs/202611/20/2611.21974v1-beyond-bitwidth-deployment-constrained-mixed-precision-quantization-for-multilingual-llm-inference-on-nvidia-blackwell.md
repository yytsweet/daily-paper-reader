## 摘要
低比特LLM量化只有在模型保持与服务相关的准确率、能够通过受支持的GPU内核执行，并满足实测内存和延迟限制时才有用。我们在NVIDIA B200上使用vLLM研究Qwen3-8B，包括INT2/INT3、GPTQ、NVFP4和混合精度配置。我们在全部144个融合线性模块上验证原生打包执行和精度，并在预注册门限下评估韩语、英语、数值和推理质量。打包的INT2和INT3可以执行，但测试的全部七种INT2网格在生成任务上均退化。孤立模块恢复效应具有强非可加性；韩语和推理的敏感性排序不一致，且一个有前景的INT4/INT8开发候选在独立最终评估中失败。一个采用16位激活、98个NVFP4仅权重量化模块、46个INT8模块和INT8输出头的配置在未触碰的FINAL-81集合（5,168项）上通过所有门限：权重加载内存5.917 GiB（限制5.98），韩语教师正确保留率0.904（门限0.90），TPOT比相对BF16为0.939。它相对于NVFP4 W4A4将配对准确率提高+1.4个百分点（Bonferroni校正区间[+0.2, +2.6]），而在选择集上为+3.4个百分点。该比较同时改变了激活精度和INT8保护；探索性分析表明激活变化贡献很大，但孤立分配效应尚未确立。最终检查点未保留，按位重建可复现性仍未验证。

## Abstract
Low-bit LLM quantization is useful only if a model preserves service-relevant accuracy, executes through supported GPU kernels, and meets measured memory and latency limits. We study Qwen3-8B on NVIDIA B200 with vLLM, including INT2/INT3, GPTQ, NVFP4, and mixed-precision configurations. We verify native packed execution and precision on all 144 fused linear modules and evaluate Korean, English, numerical, and reasoning quality under preregistered gates. Packed INT2 and INT3 execute, but all seven tested INT2 grids degenerate on generation. Isolated module-restoration effects are strongly non-additive; Korean and reasoning sensitivity rankings disagree, and a promising INT4/INT8 development candidate fails independent final evaluation. A configuration with 16-bit activations, 98 NVFP4 weight-only modules, 46 INT8 modules, and an INT8 output head passes all gates on the untouched FINAL-81 set (5,168 items): 5.917 GiB of weight-loading memory (limit 5.98), Korean teacher-correct retention 0.904 (gate 0.90), and TPOT ratio 0.939 relative to BF16. It improves paired accuracy over NVFP4 W4A4 by +1.4 percentage points (Bonferroni-adjusted interval [+0.2, +2.6]), compared with +3.4 points on the selection set. This comparison changes both activation precision and INT8 protection; exploratory analyses suggest that the activation change contributes substantially, but the isolated allocation effect is not established. Final checkpoints were not retained, and bitwise rebuild reproducibility remains unverified.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心矛盾**：低比特量化的“可行性”与“部署可行性”之间存在鸿沟。一个紧凑的 checkpoint 在加载后可能超出预期显存；一个能通过优化打包内核运行的配置可能生成不可用文本；一种格式可能输出吞吐高但首 token 延迟大，或某语言退化远大于其他语言。
- **研究立场**：低比特 LLM 量化只有**同时**满足四个条件才有部署价值：①每个融合模块都走预期的打包内核；②实测权重加载内存低于固定上限；③韩语/英语/数值/推理质量在 BF16 教师模型的预注册容差内；④TPOT 不超过 BF16 的 1.1 倍。
- **背景脉络**：GPTQ、AWQ 等权重仅量化，QuIP/AQLM 等极低比特表示，SmoothQuant/QuaRot 等激活异常值处理，HAWQ/MixLLM/IMPQ 等混合精度分配，以及 NVFP4 等微缩放格式与 Marlin/Humming/FlashInfer 等 GPU 服务内核。
- **总体含义**：量化不是单纯追求压缩比或单一 benchmark 分数，而是**数值与系统的联合问题**；测量协议（包括它拒绝什么）与格式本身同样重要。

## 2. 方法论

### 2.1 核心思想
- 以 **Qwen3-8B（36 层）** 为对象，vLLM 每层执行 4 个融合线性模块（qkv、o、gate_up、down），共 **144 个融合模块**，以融合模块为精度分配边界（负对照：同一 qkv 内混用 W4/W8 会被 vLLM 权重加载器以 shape 断言拒绝）。
- 不优化单一压缩率，而是让候选**联合通过执行、内存、质量、延迟四类约束**，并采用**预注册（preregistered）**的三阶段协议（D79 → D80 → D81）。

### 2.2 关键技术细节
- **内存门限**：使用 vLLM 原始权重加载计数器（模型加载期间已分配 GPU 内存的增量）：
  - $M(c) = \text{weight\_load\_bytes}(c)/2^{30} < 5.98\ \text{GiB}$（严格不等式）
  - 分配阶段用历史测量 + 32 MiB 安全边际预测，但**预测不算通过**；须先跑不读选择集的 smoke job 实测。该计数器不含 KV cache 与运行时激活。
- **质量门限**：定义教师正确保留率 $r_a(Q)=P(Q\ \text{correct}\mid T\ \text{correct})$ 与准确率变化 $\Delta_a(Q)=acc_a(Q)-acc_a(T)$；通过条件为 tier（四轴池化保留率）≥0.90、$r_{ko}$≥0.90、整体/数值/推理准确率变化各≥−0.03、生成项畸形输出率上升≤2 点。
- **配对主指标**（式 3）：$\Delta(Q,R)=\frac{1}{n}\sum_{i=1}^{n}[C_Q(i)-C_R(i)]$，配合正态近似区间；D81 中 track A（四比特类，k=2，z=2.2414）、track B（三比特类，k=5，z=2.5758）做 Bonferroni 校正，优越性要求校正后下界 > 0。
- **执行验证**：逐模块记录内核名、存储权重类型、激活策略、输出头、是否存在浮点回退、模型 revision 与原始内存计数（因 INT4/INT8 同走 Marlin，仅看内核名不足）。
- **敏感性诊断与分配**：从全量化基底出发，每次将一个模块恢复为 BF16，记录各轴教师正确保留率变化；冻结脚本按联合恢复效应（或韩语加权变体）排序，第二冻结脚本按内存预算自上而下填充，遇到第一个放不下的模块即停止。作者明确这是**贪心启发式**，非交互感知最优分配，且部署时用 INT8 保护而非 BF16。
