## 摘要
长程智能体任务要求模型在10万token或更长的上下文中通过多步调用工具，然而许多低比特量化方法是在短网页文本上校准并以困惑度为评判标准。这种错配代价高昂：现有对Qwen3.8-27B的每权重3比特或以下的量化，在AIME等较短任务上能与BF16持平，但在已发表结果中，在长程智能体基准DeepSWE上最多只能解决BF16可解决任务数量的72%。我们提出NariQ，一种网格编码训练后量化方法，它在智能体会话中由BF16模型生成的token上进行校准。在Qwen3.8-27B上，NariQ在每权重3.0比特和2.5比特时，在两个长程智能体基准DeepSWE和Terminal Bench上，以及在AIME和RealWorldQA上，均与BF16保持持平。我们每权重2.0比特的检查点性能落后于这一水平。据我们所知，这些是首批在长程智能体任务上被证明能与其全精度版本相匹配的、每权重3比特或以下的量化。我们将文件发布为Qwen3.8-27B-NariQ-GGUF（https://huggingface.co/nari-labs/Qwen3.8-27B-NariQ-GGUF），推理可通过我们的llama.cpp分支获取：https://github.com/nari-labs/nari-llama.cpp。

## Abstract
Long-horizon agentic tasks require a model to call tools over many steps at contexts of 100K tokens or more, yet many low-bit quantization methods are calibrated on short web text and judged on perplexity. This mismatch is costly: existing quantizations of Qwen3.8-27B at or below 3 bits per weight match BF16 on shorter tasks like AIME, yet in published results solve at most 72% as many tasks as BF16 on DeepSWE, a long-horizon agentic benchmark. We propose NariQ, a trellis-coded post-training quantization method that calibrates on tokens generated by the BF16 model in agent sessions. On Qwen3.8-27B, NariQ at 3.0 and 2.5 bits per weight stays level with BF16 on two long-horizon agentic benchmarks, DeepSWE and Terminal Bench, as well as on AIME and RealWorldQA. Our checkpoint at 2.0 bits per weight trails this performance. To our knowledge, these are the first quantizations at or below 3 bits per weight shown to match their full-precision version on long-horizon agentic tasks. We release the files as Qwen3.8-27B-NariQ-GGUF (https://huggingface.co/nari-labs/Qwen3.8-27B-NariQ-GGUF), with inference available through our llama.cpp fork at https://github.com/nari-labs/nari-llama.cpp.

# NariQ 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：语言模型越来越多被用作智能体（agent）执行长程任务。论文以 DeepSWE 为例：单个任务平均约 150 次工具调用、耗时约 50 分钟、上下文中位数 92K token。
- **核心矛盾**：现有低比特量化方法普遍在**短网页文本**上校准、以**困惑度（perplexity）和短基准**评判，与智能体实际部署分布严重错配。
- **量化代价的量化证据**：Qwen3.8-27B 在 4 bit 附近（如 NVIDIA NVFP4）尚能保持智能体性能；但在 ≤3 bpw 时，GSQ-RCO IQ3_XXS 在 AIME 上仅比 BF16 低 0.8 分（96.9 vs 97.7），在 DeepSWE 上却只能解出 BF16 的 63%；据 Unsloth 报告，所有 ≤3.0 bpw 文件最多达到 BF16 的 72%。
- **现实意义**：若能在 ≤3 bpw 保持智能体能力，则强智能体可跑在 8–32 GB 消费级 GPU 上。
- **关键判断**：论文认为瓶颈不在权重格式本身——随机旋转后权重接近高斯，2 bit 下 trellis code 已距率失真界约 10%（MSE 0.069 vs 0.063）；真正的突破口是**"该让哪些 token 正确"**，即校准目标与比特分配的对象选择。

## 2. 方法论（NariQ）

### 2.1 整体流程

1. 对每个旋转后的矩阵做 trellis 量化（QTIP 的 bitshift trellis + 计算式码本），沿用 YAQA 的输入/输出双侧统计补偿舍入误差（默认双侧，除非单侧使留出曲率加权误差再降 ≥5%）；
2. 在若干整数宽度下量化各模块；
3. 由梯度估计各模块 loss；
4. 在比特预算内分配宽度（多选背包）；
5. 调优 scales 与 norm 权重。

### 2.2 四项关键改动

**（1）端到端 loss 只计"模型自己写的 token"**

- 设 M 为 BF16 生成的 token 位置，目标函数为：
  L = (1/|M|) Σ_{t∈M} KL( p_BF16(·|x_<t) ‖ p_θ̂(·|x_<t) )
- 前缀 x_<t **包含**工具输出等上下文，mask 只选预测目标、不删上下文。动机是 agent 轨迹中工具输出与文件内容会淹没全 token loss。

**（2）按各模块自身 loss 分配宽度（修正 RCO 的失效）**

- 二阶展开下总 loss 近似为各模块项之和，单模块在宽度 k 的 loss 为 ℓ_k = ½⟨E_k, H E_k⟩。
- 指出 RCO 的一阶打分 ⟨G, W_k − W_c⟩ 在 trellis 下失效：不同宽度的误差**几乎不相关**（四个探针矩阵上，3-bit 误差与 2/4/5-bit 误差的曲率加权余弦仅 0.035 / 0.009 / 0.004），一阶项可忽略，打分退化为 ≈ −2ℓ_c，丢失了目标宽度的 loss 信息。
- NariQ 改为：把 ½⟨G, W_c − W_k⟩ 对 k≠c 取平均来**估计当前宽度的 ℓ_c**；再假设 loss 随码的 MSE 成比例外推 ℓ_k ≈ ℓ_c · r_k / r_c（r_k 为实测 MSE，每加 1 bit 约降 4×，故 2 bit 的 loss 约为 3 bit 的 3.9 倍）。
- 为抑制外推噪声：融合多组宽度分配下的估计，重缩放至统一宽度后按逆方差加权，取**均值 + 2 倍标准误**并加小正下限。
- 分配目标为 min Σ_m ℓ̂_{m,k_m}，s.t. C_fixed + Σ_m n_m k_m ≤ BN，用**离散预算上的动态规划**求解，偏向最满的可行分配，并用精确成本检查强制存储上限（不保证全局最优）。
- 经验发现：1 bit 下 loss 估计失效（2.0 bpw 时把分配器放在 1 bit 的 12 个模块提到 2 bit，仅多 0.021 bpw 就降 7.2% KL），因此**所有线性层 ≥2 bit**。

**（3）输出层按 token 概率分带（banding）**

- 输出层 248,320 个 token 中仅约 13% 在校准轨迹中作为生成 token 出现，但每行都参与 softmax。
- 依据：token 概率为 p 时，其 logit 的 KL 曲率 ∝ p(1−p) ≈ p，故按**平均预测概率**排序，分成 16 个约 15,500 行的带，每带作为独立模块单独分配宽度。
- 稀有 token 仍需精度：1 bit 带在多语言等稀有 token 轨迹上反而升高 KL，故**每带至少 2 bit**；3.0 bpw 下分带使平均每 trial KL 降 12.1%。
- 2.0 bpw 时输入嵌入也分带（按 token 在输入中出现频率排序，且稀有带允许 1 bit）。

**（4）尺度调优数据混合**

- 固定码与宽度后，调所有编码矩阵的 scales 与 norm 权重，数据为 coding agent 轨迹 + BF16 对通用提示（数学、科学、对话、代码、长文档）的回复，权重 **70:30**。
- 消融证据：早期仅用 coding 轨迹的 2.0 bpw 文件 AIME 仅 77.3%（BF16 97.7%），加入通用数据后升至 86.0%。

### 2.3 发布格式

- 以 GGUF 发布；每矩阵用 2 的幂大小的随机 Hadamard 块旋转，attention 与 DeltaNet 层多数矩阵一侧先做种子置换；块大小与具体模型解耦；码本由 trellis 状态计算（同 EXL3），核函数在矩阵乘内部解码。

  - **Terminal Bench 2.1**：取 Unsloth 报告的 82 个任务，**每任务 3 次尝试**，取平均 test reward。
