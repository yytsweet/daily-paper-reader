ABSTRACT
In recent years, GPUs have incorporated increasingly specialized support for low-precision computation, from
Hopper’s FP8 to Blackwell’s FP4 Tensor Cores. Precision formats have evolved alongside this hardware, from
MXFP4 and NVFP4 on Blackwell to E2M1 FP4 with direct UE5M3 block scaling on Vera Rubin, which we term
as VRFP4. These advances help serve larger language models at lower cost, but four-bit activation quantization
can substantially degrade model quality. We introduce VR-SparseQuant, which uses Vera Rubin’s elementwise
2:4 sparsity to recover accuracy while retaining native FP4 execution. By allowing two sparse streams to overlap,
we use the same FP4 value budget as dense quantization to refine activations with larger errors. Offline scale-ratio
calibration avoids runtime search, while a shared-weight GEMM accumulates both streams efficiently. On
Nemotron-3-Nano-30B-A3B, VR-SparseQuant reduces WikiText-2 perplexity from 6.85 to 5.57 versus dense
RTN W4A4. Including activation preparation, our native Rubin kernels for VRFP4 achieve up to 3.1× GEMM
and 2.7× MoE speedup over BF16. To the best of our knowledge, this is the first study of adaptive activation
quantization using Vera Rubin’s elementwise 2:4 structured sparse FP4 instructions.

Recent advances in large language model (LLM) inference
have made low-bit execution practical for interactive gen-
eration and large-batch serving (Lin et al., 2024; 2025).

fic while retaining higher-precision activations (Lin et al.,
2024). Native FP4 also lowers compute cost, but requires
four-bit activations encoded online, unlike weights quan-
tized and packed offline. This encoding must preserve qual-
ity with little work and fit native instructions. Preparing
models for NVIDIA’s Vera Rubin platform therefore re-
quires designing quantization around its arithmetic, scales,
and sparse layouts (NVIDIA, 2026i;g).
Dense FP4 gives every activation one four-bit code and a
shared block scale. Fixed slots simplify online packing but
allocate values uniformly despite unequal errors. When
large values set the scale, smaller values may be poorly re-
solved; smoothing and adaptive scales improve the fit (Xiao
et al., 2023; Cook et al., 2025). Some positions still ben-
efit more from a second contribution correcting rounding
error than others. Existing methods add residual channels
or sparse–dense branches (Meng et al., 2026a;b; Mak et al.,
2026). Reallocating a fixed value budget instead requires
choosing which positions to cover and correct while con-
structing native operands online.
Structured sparsity makes these choices through local posi-
tion metadata while keeping value count and operand for-
mat fixed. Blackwell’s compact sparse FP4 path selects
adjacent pairs; Vera Rubin selects two individual positions
per quartet (NVIDIA, 2025c; 2026g). Neither variable-
length records nor input-dependent weight permutations are
needed.
We introduce VR-SparseQuant (VR-SQ), which represents
an activation as the sum of two structured 2:4 sparse matri-
ces with different scales to better separate value ranges and
improve quantization accuracy. We refer to each matrix as
a stream, which retains the input’s logical shape but stores
only two FP4 values per quartet, together with scales and
position metadata. Together, they match dense FP4’s value
count and nonzero arithmetic, but their sparsity patterns
can overlap: the fine stream can represent an uncovered
value or correct the coarse stream’s approximation. Over-
lap leaves another position uncovered, so it is useful when
correction removes more error than the omission introduces
(Figure 1a).
Scales and positions are coupled, so a joint search repeatedly
encodes each block. After smoothing and weight quantiza-
tion, we instead calibrate the scale ratio offline. It ties the
fine scale to the coarse scale while both track each block’s
range. Two local selections then assign coarse values and
fine residual corrections without searching scale pairs on-
line.
A preparation kernel constructs both streams together. A
single sparse GEMM shares staged weight tiles across both
streams and uses one FP32 accumulator, avoiding duplicate
global-memory weight-tile loads, materialized intermediate
outputs, and a combining pass. The kernels apply Rubin’s
UE5M3 block scales directly to E2M1 values, a format we
call VRFP4.
We evaluate dense and mixture-of-experts language mod-
els and vision-language models on language modeling,
reasoning, agentic tasks, and visual understanding. GPT-
OSS (OpenAI, 2025) and MiniMax (MiniMax, 2026) test
adaptation from released MXFP4 and NVFP4 checkpoints
without original BF16 weights. Coverage studies progres-
sively quantize more projection families; ablations examine
smoothing, scales, and assignment. Including online acti-
vation encoding, native GEMM and MoE on Vera Rubin
achieve 1.7–3.1× and 1.4–2.7× speedup over BF16, re-
spectively; dense FP4 comparisons quantify the additional
latency of this allocation.
To the best of our knowledge, this is the first study to design
and evaluate adaptive activation quantization using Vera
Rubin’s compact elementwise sparse FP4 instructions. It
connects a representation that improves model quality with
kernels that execute it natively on Rubin. The broader con-
tribution is a practical use of structured sparsity to allocate
precision: sparse position metadata lets each input deter-
mine where a fixed budget of FP4 values is spent.

PRELIMINARIES: FP4 ON VERA RUBIN
For a linear layer Y = XW ⊤with M rows, K input chan-
nels, and N output channels, the representation depends
on which positions an operand may store and which values
share a scale.
2.1
Elementwise Sparse FP4
A 2:4 sparse operand stores two values and their positions
per quartet along K. Sparse Tensor Cores multiply only
these entries, halving nonzero arithmetic relative to a dense
product.
The allowed positions depend on the instruction format (Fig-
ure 2). Ampere FP16 and Hopper FP8 support elementwise
2:4 sparsity. Blackwell’s compact sparse FP4 path selects
two adjacent pairs from eight positions; Rubin’s element-
wise FP4 path selects two individual positions per group of
four (NVIDIA, 2025c; 2026g). Both retain half the values,
but neither mask family contains the other.
Our selected Rubin path shares one scale across 16 stored
values (32 logical positions) and uses G32 weights.
2.2
Block Scales and Group Size
Microscaling combines low-bit values with scales shared
across small blocks (Darvish Rouhani et al., 2023). E2M1
uses one sign bit, two exponent bits, and one fraction bit.
Group size G governs scale sharing; the scale format deter-
mines range and precision.
NVFP4 combines unsigned E4M3 (UE4M3) scales for 16-
value blocks with an FP32 tensor scale (NVIDIA, 2026f):

3.1
Two-Stream Quantization
We encode the prepared input U = BF16(X⊙b), where b is
a positive channel transform fixed during model preparation.
Its inverse is absorbed into the weights (Section 3.4). For a
block u ∈R32 of this input, we write u ≈a1 + a2, where
each stream stores two FP4 values per consecutive group
of four and one scale for the block. The scales S1 and S2
define coarse and fine grids. Across the streams, a logical
position can receive zero, one, or two selected contributions,
while each stream retains its fixed 2:4 layout. A stream’s
sparsity pattern specifies its selected positions; a selected
code can itself be zero. Section 4 accounts for the additional
metadata and scales.
If the two sparsity patterns are disjoint, every activation is
represented once; we call this assignment complementary.
Allowing overlap lets the fine stream encode the coarse
stream’s residual. This trades coverage for correction: an
overlap is useful when the error removed at one position
exceeds the error introduced by leaving another position
uncovered.
Figure 4 shows these choices in Qwen3.5-4B-Base activa-
tions. Squares and triangles on the axes have one nonzero
contribution; off-axis circles have two. The fine contribution
can be positive or negative, adjusting the coarse reconstruc-
tion in either direction. Combining the grids thus makes
additional reconstruction levels available without increasing
the FP4 value budget.
Encoding each block requires two choices: the scales of
the two grids and the positions selected by each stream.
Jointly searching both online would repeat assignment for
each candidate scale pair. To keep encoding lightweight, we
calibrate the scale ratio offline and fix it at inference. We
then derive both scales from the block maximum and assign
values through two greedy selections.

Scale Selection
The coarse scale follows the current block maximum, while
the calibrated ratio p determines the fine scale:
S1 = RNUE5M3(max |u|/6),
S2 = RNUE5M3(pS1),
0 < p ≤1.
(1)
Here 6 is the largest E2M1 magnitude. For finite, nonnega-
tive inputs, RNUE5M3 applies round-to-nearest, ties-to-even
conversion with finite saturation, clamps the scale code to
[1, 254], and returns its decoded value. This encoder pol-
icy keeps both scales positive, including for all-zero blocks.
Both scales apply to the same 32 positions and adapt to each
block, while p stays fixed.
Reducing p gives the fine grid smaller reconstruction steps
near zero but narrows its range. Calibration minimizes
activation-induced output error (Section 3.5), leaving no
runtime scale search.

to selecting two gains within each quartet.

EXECUTION ON VERA RUBIN
Adaptive assignment adds online work and metadata traf-
fic. Efficient execution must control these costs while pro-
cessing both streams without duplicating global-memory
weight-tile loads or outputs. We prepare and pack weights
offline, with channel transforms and scale ratios fixed before
inference. At runtime, a fused preparation kernel encodes
the activations, followed by a shared-weight sparse GEMM.
4.1
Fused Activation Preparation
Each new input requires selecting and packing two sparsity
patterns. We fuse the channel transform, scale computa-
tion, greedy assignment (Section 3.3), and packing into
one kernel. The coarse scale uses the transformed input
block’s maximum; the fine scale is derived using the cal-
ibrated ratio, avoiding a second maximum reduction over
the residual. The kernel writes FP4 codes, UE5M3 scales,
and position metadata while preserving the original K po-
sitions, so changing sparsity patterns requires no weight
rearrangement.
The FP4 value budget is unchanged, but metadata and scales
add traffic: each G32 block stores 16 bytes of values, 8
bytes of position metadata, and 2 bytes of scales. This is 6.5
bits per logical activation before padding and replication,
compared with 4.5 bits for dense G16 FP4, excluding any
tensor-level factor.
4.2
Shared-Weight Sparse GEMM
Both streams multiply the same weights. Our GEMM shares
each weight tile staged in shared memory across both sparse
streams, avoiding a separate global-memory weight-tile load
for the second stream. Both products update one FP32 accu-
mulator. The epilogue converts the result to BF16 without
materializing intermediate products.
Together, the products perform dense GEMM’s 2MNK
nonzero FLOPs. Our latency measurements include both the
activation-preparation kernel and the shared-weight GEMM,
capturing the cost of assignment and additional metadata
traffic (Section 5.2).
For a standard projection, preparation reads the incoming
activation tensor. In grouped MoE, preparation for the first
expert GEMM follows token dispatch; preparation for the
second follows the intermediate activation. Routing and the
weighted combination of expert outputs remain unchanged.

Attention projections can be sensitive to quantization. We

RELATED WORK
Dense low-bit quantization.
SmoothQuant transfers ac-
tivation dynamic range to weights, while AWQ protects
sensitive weight channels using activation statistics (Xiao
et al., 2023; Lin et al., 2024). QuaRot and SpinQuant use
rotations, and FlatQuant learns affine transformations, to
improve dense weight and activation quantization (Ashk-
boos et al., 2024; Liu et al., 2025; Sun et al., 2025). For
microscaled FP4, Four Over Six selects between two block
scales, and MR-GPTQ combines format-specific quantiza-
tion with blockwise rotations (Cook et al., 2025; Egiazarian
et al., 2026). These methods improve dense quantizers’ co-
ordinates or grids. VR-SparseQuant instead allocates FP4
contributions across positions through sparse metadata and
remains complementary to weight quantization and channel
smoothing.
Structured sparse decomposition.
TASD approximates
weights and activations with multiple structured sparse ten-
sors and sums their products (Jeong et al., 2025). SDQ de-
composes weights into structured sparse components with
different precisions and error-aware selection (Jeong et al.,
2024). VR-SparseQuant’s two FP4 activation components
can overlap, letting one value correct another’s rounding
error. Their combined value count equals dense FP4’s, so
correction competes with representing distinct positions
within a fixed allocation.
Residual correction for quantization.
SVDQuant ab-
sorbs outliers into a high-precision low-rank branch and
quantizes the residual to four bits (Li et al., 2025). ARC-
Quant adds FP4 activation-residual channels to the reduction
dimension of a single GEMM (Meng et al., 2026a). SharQ
uses a sparse FP4 backbone and a dense FP4 residual, shar-
ing one weight payload across the two products (Meng et al.,
2026b). Rollout-ResQ adds a 2:4 FP4 residual to dense FP4
activations for reinforcement-learning rollouts (Mak et al.,
2026). VR-SparseQuant constrains both components to 2:4
sparsity. Its residual stream must choose between covering
omitted values and correcting represented ones; a calibrated
scale ratio and online error-based selection make this choice
without searching scale pairs at inference.
Sparse execution.
Haziza et al. exploit Squared-ReLU
activation sparsity with online 2:4 packing and fused FP8
quantization (Haziza et al., 2025). Attention and token spar-
sity operate at a different level, reducing the tokens or spatial
locations processed (Xiao et al., 2024; Yang et al., 2025;
Liu et al., 2024; Khaki et al., 2025). For low-bit execution,
TinyChat, QServe, and Nunchaku control dequantization,
data movement, and branch overhead (Lin et al., 2024; 2025;
Li et al., 2025). ARCQuant and SharQ integrate residual
preparation with FP4 execution (Meng et al., 2026a;b). VR-
SparseQuant reuses weight tiles and an accumulator for both
sparse products in one GEMM on Rubin’s compact elemen-
twise FP4 path (NVIDIA, 2026g). SpAtten (Wang et al.,
2021) proposes KV Cache sparsification and quantization,
we well as the combinations of them.

LIMITATIONS
VR-SparseQuant improves activation precision through ad-
ditional encoding work and metadata traffic, which can
increase latency relative to dense W4A4. The sparse FP4
Tensor Core path we use requires G32 weights, sacrificing
scaling granularity relative to the dense G16 baseline. This
can introduce additional weight quantization error that ac-
tivation encoding cannot directly correct. Stronger weight
quantizers are therefore particularly important for mitigating
this penalty and retaining the gains from activation encod-
ing (Table 10). Reported speedups cover GEMM and MoE
operators, excluding communication and other serving over-
heads. Native kernel measurements use Vera Rubin; the
sparsity-pattern comparisons assess simulated quality. Re-
sults for complete recipes and converted checkpoints reflect
both weight and activation effects, while the fixed-weight
ablations isolate activation encoding.
8
CONCLUSION
To the best of our knowledge, this is the first study to design
and evaluate adaptive activation quantization using Vera
Rubin’s compact elementwise 2:4 sparse FP4 instructions.
VR-SparseQuant uses sparsity patterns to allocate precision:
two overlapping streams refine selected activations while
retaining dense FP4’s value count and nonzero arithmetic.
Offline calibration, greedy assignment, and a shared-weight
GEMM make this allocation practical. Our kernels use Vera
Rubin’s direct UE5M3 block scaling for E2M1 FP4, which
we term VRFP4.
Across RTN, AWQ, and Four Over Six, VR-SparseQuant
improves perplexity relative to dense W4A4, with further
applications to vision-language models and released low-bit
checkpoints. Including online activation preparation, native
Rubin kernels achieve up to 3.1× GEMM and 2.7× MoE
speedup over BF16.
More broadly, Rubin’s elementwise selection and VRFP4
scaling show how new hardware capabilities expand the
design space of quantization. More flexible sparsity pat-
terns, lower metadata costs, and tighter fusion of encoding

with surrounding operators could make adaptive precision
allocation more efficient. These results motivate developing
quantization formats, algorithms, and kernels together as
GPU hardware evolves, with model quality, memory traffic,
and latency as joint design objectives.

primarily supported the development and iterative refine-
ment of computational kernels. Verifiable objectives guided
this process, enabling successive improvements in kernel
efficiency through an approach similar to that explored in

ing and improve the clarity and readability of explanations,
helping communicate the work more effectively.
