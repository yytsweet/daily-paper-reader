MiSTiQ: MicroScaling Trellis Quantization for Extreme KV Cache Compression
Ofir Gordon 1 Lior Dikstein 1 Paul Balanca 2 Idan Achituve 1 Douglas Orr * 2 Hai Victor Habi * 1
Abstract
Modern large language models (LLMs) increas-
ingly support longer contexts and serve more
concurrent requests, increasing both sequence
lengths and batch sizes. Both trends increase
KV-cache size and memory traffic during in-
ference. KV-cache quantization reduces these
costs, with recent approaches using codebook-
based vector quantization to achieve extremely
low bit widths. However, hardware constraints
limit codebook size, and most methods recon-
struct the cache in higher-precision floating-point
formats for attention, limiting the computational
benefits of quantization. To address these limi-
tations, we introduce MiSTiQ, a drop-in replace-
ment for codebook-based vector quantizers that
combines trellis-coded storage with microscaling
(MX) formats for low-precision computation. We
combine trellis quantization with beam search
to encode the KV cache over large reconstruc-
tion spaces without large codebooks. To sup-
port MX computation, we derive MX-Hash func-
tions that generate reconstruction values directly
in the target MX element format. These functions
use the scale-conditioned marginal distribution of
block-normalized Gaussian inputs. On Llama3
and Qwen3, MiSTiQ achieves lower WikiText
perplexity and higher GSM8K accuracy than the
evaluated baselines across several block-scale for-
mats at approximately 1.25 effective bits per ele-
ment. With NVFP4, it also achieves the highest
LongBench average on both models.

to reduce memory, as well as its applicability to pretrained
models without requiring extensive retraining.
KV-cache quantization methods exploit the different dis-
tributions of keys and values to reduce storage while pre-
serving accuracy. KIVI (Liu et al., 2024) uses different
quantization granularities for keys and values, while more re-
cent methods adopt vector quantization to improve accuracy
at lower storage budgets. These include NSNQuant (Son
et al., 2026), which uses calibration-free distribution shaping
through normalization and scaling, and VecInfer (Yao et al.,
2026), which applies smoothing and Hadamard transforma-
tions to mitigate key-cache outliers. These methods store the
quantized cache as integer codes and use floating-point or in-
teger arithmetic for computation. However, codebook-based
vector quantization is constrained by the size of the code-
books that hardware can efficiently support. QTIP (Tseng
et al., 2024b) addresses this limitation for weight quantiza-
tion through trellis quantization, enabling large reconstruc-
tion spaces without explicitly storing large codebooks.

Here, we aim to reduce KV-cache storage while enabling

precision computation. To achieve this, we address the

for KV-cache compression. We then augment trellis quanti-

tional benefits. The resulting approach is a drop-in quantizer
that can replace vector quantization and be integrated with
most methods. Concretely, we introduce Microscaling Trel-
lis Quantization (MiSTiQ), which replaces QTIP’s Viterbi
encoder with beam search and uses MX-Hash functions
based on the distribution of block-normalized Gaussian ele-

into the beam search with the finer-resolution UE5M3 (Fa-
soli et al., 2026) scale format. To the best of our knowledge,
MiSTiQ is the first dedicated KV-cache quantizer to com-
bine sub-2-bit effective storage with direct reconstruction
into MX-compatible formats. Experiments on WikiText,
LongBench, and GSM8K demonstrate improved accuracy
over the evaluated baselines across a range of models and
quantization settings.

for using QTIP as a storage format while leveraging MX
formats for computation. This paper makes the follow-

cache; (2) we develop QTIP hash variants tailored to match

that demonstrate the benefits of the proposed method. To
support reproducibility, we will publicly release the code
implementing our method upon acceptance. The appendix
is provided separately as supplementary material.
2. Related Work
KV-cache compression.
The growing memory and band-
width costs of KV caches under long contexts and large
batches have driven extensive research into cache com-
pression. Among these approaches, quantization has been
widely studied as a means of reducing the storage cost per
cached element while retaining the cached tokens. KIVI
uses per-channel key and per-token value quantization (Liu
et al., 2024), while KVQuant combines pre-RoPE key quan-
tization with sensitivity-weighted nonuniform levels and
outlier handling (Hooper et al., 2024). Rotation-based ap-
proaches, including QuaRot, RotateKV, and TurboQuant, re-
shape the quantization domain to improve low-bit represen-
tations (Ashkboos et al., 2024; Su et al., 2025; Zandieh et al.,
2026). Codebook-based vector quantization instead exploits
dependencies across coordinates, using coupled channels
or additive representations (Zhang et al., 2024; Li et al.,
2025a). NSNQuant specifically combines double normaliza-
tion, channel centering, and Hadamard transforms to support
a reusable Gaussian codebook without data-dependent cali-
bration (Son et al., 2026). VecInfer combines smoothing and
Hadamard transforms to improve codebook utilization, with
fused dequantization and attention computation (Yao et al.,
2026). Motivated by differences in quantization sensitivity,
particularly the greater sensitivity of keys, mixed-precision
methods allocate bits according to K/V and layer sensitiv-
ity (Li et al., 2025b; Tao et al., 2025), token saliency (Dong
et al., 2024; He et al., 2024), or recency and progressive
quantization schedules (Duanmu et al., 2024; Liu et al.,
2026). Complementary approaches like AQUA-KV exploit
reconstruction structure: quantizes residuals from learned
predictors (Shutova et al., 2025). Other compression mech-
anisms include token selection and eviction (Zhang et al.,
2023; Li et al., 2024), head-dependent cache retention (Xiao
et al., 2025), and low-rank cache representations (Chang
et al., 2025).
Trellis quantization.
Trellis-coded quantization repre-
sents source sequences through paths in a finite-state trellis,
with subsequent extensions assigning vector reconstructions
to trellis branches (Marcellin & Fischer, 1990; Fischer et al.,
1991). This structure couples successive reconstruction
choices while permitting encoding by dynamic program-
ming, avoiding an explicit enumeration of all possible recon-
structed sequences. For low-bit LLM weight compression,
QuIP# combines randomized Hadamard preprocessing with
E8 lattice codebooks at up to four bits per weight (Tseng
et al., 2024a), while AQLM uses sums of learned codewords
with joint optimization within transformer blocks, targeting
two to three bits per parameter (Egiazarian et al., 2024).
However, the size of an explicit, unstructured codebook
grows exponentially with vector dimension at a fixed bi-
trate. QTIP combines trellis quantization with incoherence
processing, using a stateful bitshift trellis to decouple the
effective quantization dimension from the stored codebook
size (Tseng et al., 2024b). It supports both lookup-based
and computed, lookup-free reconstruction rules, offering dif-
ferent tradeoffs between storage and computation. Proteus
further develops lookup-free trellis quantization through

computed reconstruction codes (Yang et al., 2026).
MX quantization.
Microscaling (MX) formats combine
low-precision floating-point or integer elements with a
shared block scale, extending their representable dynamic
range (Rouhani et al., 2023). Early work adapted established
post-training quantization algorithms to MX formats (Shar-
ify et al., 2024), while subsequent studies examined the ef-
fects of element format and quantization granularity (Chen
et al., 2026). Format extensions such as MX+ and AMXFP4
improve outlier representation through enhanced element
precision and asymmetric shared scales, respectively (Lee
et al., 2025a;b). Rotation-based approaches, including MR-
GPTQ and Block Rotation, use block-local transformations
tailored to MX scaling constraints (Egiazarian et al., 2026;
Shao et al., 2026). FPTQuant also reshapes activations and
improves weight–activation alignment for low-bit integer
quantization (van Breugel et al., 2026). For MX quanti-
zation, LATMiX extends distribution shaping beyond rota-
tions through learned invertible affine transformations that
account for the activation distribution and MX block struc-
ture (Gordon et al., 2026). Complementary approaches im-
prove scaling through pre-scale optimization (Zhang et al.,
2026), overflow-aware scale selection, and higher-precision
scales shared across larger blocks (Chhugani et al., 2026).

3.2. QTIP
Vector quantization (VQ) represents a group of V values by
one index selecting a reconstruction vector from a codebook.
Jointly chosen reconstruction vectors can provide better
shaping than independent scalar quantization. At k bits per
element, however, an unrestricted V -dimensional codebook
contains 2kV entries, so its storage and nearest-neighbor
search cost grow exponentially with V .
Trellis quantization represents long vectors that would be
intractable with an unrestricted codebook as a walk through
a trellis. QTIP (Tseng et al., 2024b) uses a (L, k, V ) trellis,
where L is the state-bit length, k is the coded bit rate per
scalar, and V is the number of scalars emitted at a trellis
step. A length-T source is divided into n = T/V groups
rt ∈RV for t = 1, . . . , n, assuming V | T. The state set is
U = {0, . . . , 2L−1}. The reconstruction map C : U →RV
assigns a code value to each state. It may use a stored
codebook lookup or a computed QTIP code.

4. Quantization with Beam Search on Trellises
To enable trellis quantization of the KV cache while limiting
encoding overhead, we replace the exact Viterbi search used
by QTIP with approximate beam search.
Let bstart denote the number of bits used to select the ini-
tial trellis state. Beam search considers initial states in
{0, . . . , 2bstart −1} and retains at most B ≥1 path hypothe-
ses after each expansion. Let Bt be the indexed collection
of retained hypotheses after step t. Each hypothesis h ∈Bt
has its own terminal state ut(h) ∈U, accumulated dis-
tortion Jt(h), and predecessor-hypothesis index. Initialize
B0 = {0, . . . , 2bstart −1}, with u0(h) = h and J0(h) = 0
for each h ∈B0. Setting bstart = 0 gives the fixed ini-
tial state u0 = 0. For each retained hypothesis h ∈Bt−1,
expand every legal successor v ∈succ(ut−1(h)) with cost
eJt(h, v) = Jt−1(h) + ℓt(v).

Keep up to B lowest-cost expanded hypotheses across all
parents and assign them indices in Bt. At termination, select
a minimum-cost retained hypothesis and trace its predeces-
sor indices to recover its path. Algorithm 1 includes a
summary of the encoding procedure.
The state sequence u1:n is the logical encoder output. Its
compact stored representation comprises the branch labels
ct = ut mod 2kV , each occupying kV bits, together with
the selected initial state u0, represented by bstart bits. The
initial-state selector contributes bstart/T bits per scalar.
When bstart = 0, the decoder uses u0 = 0 without stor-
ing a selector. Decoding consists only of state recovery,
reconstruction-map lookup, and concatenation, without
beam search or optimization. The procedure is summarized
in Algorithm 3.
QTIP’s optimized Viterbi search considers up to 2L trellis
states and has complexity O(2LT/V ). Beam search ex-
pands 2bstart initial hypotheses and at most B hypotheses
at each subsequent step, scoring their 2kV successors and
requiring O((2bstart+(T/V −1)B)2kV ) work for direct dis-
tortion evaluation, plus selection. This reduces the retained
search space at the cost of losing guaranteed optimality,
while decoding remains unchanged.

5.2. Relaxed Joint Scale Search
A straightforward approach to encoding y is to first choose
the scale sb for each MX block according to a heuristic
rule, such as scaling the maximum to fit in the element
quantizer’s range (see Section 3.1). The normalized blocks
are then quantized via beam search, with each sb held fixed.

scales and trellis encodings during beam search. Unlike
NSNQuant’s post-quantization scale adjustment (Son et al.,

change the reconstruction error of previous values.

5.3. Mixed Precision KV Quantization
Prior work has shown that keys are more sensitive to quanti-
zation than values (Li et al., 2025b; Tao et al., 2025). Our
payload-allocation analysis in Figure 6 supports this ob-
servation for MiSTiQ, showing that allocating more bits
to keys can improve accuracy under a fixed total payload
budget. Following this approach, we extend MiSTiQ to
support different transition-bit budgets for the key and value
trellis encoders, assigning more bits per transition to keys
and fewer to values.
This allocation becomes more flexible as the vector length
V increases. Since each trellis step emits V scalar values, a
one-bit change in the transition budget changes the payload
by 1/V bits per element. Larger vectors therefore enable
finer-grained allocation of the available payload between
keys and values.
The computed reconstruction mapping of MiSTiQ supports
this flexibility without requiring an enlarged lookup table.
For an explicit, unstructured vector codebook, representing
V values at k bits per element requires 2kV entries. Its
storage requirements therefore constrain the vector lengths
and payload allocations that are practical.
6. Experiments
We evaluate MiSTiQ on Llama-3.1-8B-Instruct (Grattafiori
et al., 2024) and Qwen3-8B (Yang et al., 2025) to assess
its effectiveness for KV-cache quantization at very low bit
widths. We compare MiSTiQ with existing vector quanti-
zation methods designed for KV-cache compression, eval-
uating WikiText-2 perplexity (PPL) (Merity et al., 2017),
performance across LongBench tasks (Bai et al., 2024), and
accuracy on GSM8K (Cobbe et al., 2021) under a decode-
heavy chain-of-thought generation setting. We further con-
duct ablation studies to isolate the contributions of individ-
ual components and assess the trade-offs underlying our
design choices. We present sub-1-bit PPL results in Ap-
pendix G.1.
6.1. Experimental Settings
For the main results, we configure the MiSTiQ quantizer
with a block size of 32 (16 for NVFP4) at effective bit
widths above 2 bits per element, and 1283 below 2 bits per
element. These choices are intended to maintain compati-
bility with MX-capable hardware while allocating more of
the storage budget to trellis-coded values. For the UE5M3
and NVFP4 configurations, we use the relaxed joint scale
search described in Section 5.2.
For the main results, we integrate MiSTiQ into the
NSNQuant (Son et al., 2026) workflow as a drop-in replace-
ment for its codebook-based vector quantizer, retaining its
normalization and Hadamard transformations. Normaliza-
tion is applied before RoPE, and MiSTiQ quantization is
applied to the KV cache after RoPE. Appendix G.2 demon-
strates this integration with VecInfer, improving its accuracy
below 2 effective bits per element.
Unless otherwise stated, the trellis encoder in MiSTiQ uses
a state-bit length of L = 16 and a source vector length of
T = 1024, with V = 4 scalar values emitted per trellis step
in the higher-bit settings and V = 8 in the lower-bit settings.
Encoding uses beam search with beam width B = 128. We
implement the baseline methods following their original
descriptions and adapt them to MX formats by quantizing
their codebook elements to the target MX element format.
All experiments were conducted on NVIDIA H100 GPUs,
using one GPU per run except for GSM8K evaluations,
which used four GPUs. Full implementation details, in-
cluding per-variant transition-bit allocation, are provided in
Appendix A.

6.3. Ablation Study
6.3.1. QUANTIZER DESIGN COMPARISON
Table 2 evaluates the successive design choices under-
lying MiSTiQ using WikiText-2 perplexity at approxi-
mately matched effective storage budgets. Replacing the
NSNQuant-style codebook quantizer with trellis quantiza-
tion followed by MX conversion (Naive MX Trellis) sub-
stantially reduces perplexity on both models. Incorporat-
ing MX element constraints directly into the reconstruction
mapping (MX Trellis Hash) yields further improvements
by making the trellis search aware of the final reconstruc-
tion values. Jointly optimizing the trellis path and block
scales (MX Trellis Hash Joint) further reduces perplexity,
achieving the best results on both models. Together, these
results show that trellis quantization provides the largest
initial improvement, while MX-aware reconstruction and
joint scale search contribute additional gains.
6.3.2. VECTOR LENGTH AND PAYLOAD ALLOCATION
We next examine how the number of scalar values emitted
per trellis step, V (referred to as the “vector length”), af-
fects quantization accuracy and the flexibility of payload
allocation between keys and values. We first evaluate vector
length under uniform payloads in Figure 5, then show how
the finer-grained allocation enabled by larger vectors can
further improve accuracy with mixed precision payloads in
Figure 6.
Although a vector length of V = 4 yields the lowest per-
plexity on both models under uniform payloads, V = 8
enables finer-grained payload allocation. This flexibility
allows mixed precision configurations to assign a larger pay-
load to the more sensitive keys, further reducing perplexity.
This flexibility is particularly valuable for extremely low
effective bit regimes, where small changes in payload al-
location can substantially affect accuracy, motivating our
use of V = 8 in this regime and V = 4 in the higher-bit
configurations.
7. Conclusions
In this work, we presented MiSTiQ, a KV-cache quantizer
that combines compact trellis-coded storage with microscal-
ing formats for computation, bringing MX quantization to
the KV cache. We examined how to preserve accuracy at
very low storage budgets while reconstructing the cache
directly in MX-compatible representations. To this end, we
developed a beam-search trellis encoder that limits the re-
tained search space, enabling KV-cache quantization with
large reconstruction spaces without explicitly storing large
vector codebooks. We further introduced MX-Hash func-
tions that generate reconstruction values directly in the tar-
get MX element format. We also developed relaxed joint
search over trellis encodings and block scales, incorporating
MX constraints into the encoding process. Experiments
across language modeling, long-context understanding, and
reasoning demonstrate strong overall performance, with
particularly substantial gains at low effective bit widths.
These results motivate extending the combination of trellis-
coded storage and MX computation to weight quantiza-
tion, where offline encoding permits more extensive search.
Supporting a broader range of weight and KV-cache dis-
tributions also motivates relaxing the Gaussian assumption
underlying our hash construction, for example through re-
construction mappings adapted to empirical distributions.

MiSTiQ: MicroScaling Trellis Quantization for Extreme KV Cache Compression
A. Implementation Details
Quantizer implementation.
MiSTiQ encodes vectors as trellis paths and represented block scales, using Triton kernels
with FP32 arithmetic during search. The main implementation uses L = 16 state bits, bstart = 8 initial-state selection bits,
T = 1024, and beam width B = 128, unless otherwise specified. Reconstruction elements lie directly on the E2M1 grid,
avoiding a second MX conversion after encoding. The quantizer can be integrated with different preprocessing workflows.
We apply key-channel standardization by subtracting a frozen per-channel mean and dividing by a frozen per-channel
standard deviation before the Hadamard transform. These statistics are calibrated separately for each layer, KV head, and
key channel in the corresponding preprocessing domain, with standard deviations floored at 10−6. After reconstruction and
inverse Hadamard transformation, we restore the original channel scales and means.
MX-Hash calibration.
Hash resources are prepared separately for each element format, scale format, vector length,
and search policy. For the initial-scale variant, integer CDF boundaries are precomputed for each represented scale value,
allowing a 31-bit hash rank to map directly to an MX element without evaluating an inverse CDF at runtime. The mixer
parameters for each output coordinate are calibrated jointly over synthetic inputs, rather than independently for every scale
value. The joint-scale variant instead calibrates the mixers and the spread of a symmetric Gaussian emission distribution on
the native element grid, producing a scale-independent mapping.
We select the post-LCG mixing parameters through reproducible offline random search, keeping the LCG coefficients
Aℓ, Cℓfixed. Each candidate jointly specifies all V output coordinates: three shifts per output coordinate sampled uniformly

The standard calibration evaluates 48 candidates using 32 training vectors of length 128 and 256 held-out vectors. The initial

Block-scale computation and search.
For each input block, we first compute the reference scale as its maximum absolute
value divided by the element-format maximum, which is 6 for E2M1, and round it to the selected scale format. In the
initial-scale option, this represented scale remains fixed throughout encoding, and the hash uses its scale-conditioned
mapping. In the joint-scale option, each retained path accumulates the target–emission inner product and emission squared
norm. These statistics support a continuous least-squares scale update at each step, regularized toward the reference scale
for incomplete blocks. The fitted scale is rounded before candidate scoring; at block completion, the scale is refitted without
regularization. The joint mapping remains independent of the fitted scale, so decoding requires only one stored output scale
per block.
Our experiments use initial-scale search with UE8M0 and joint-scale search with UE5M3 and NVFP4. UE8M0 scales
round upward; UE5M3 uses nearest rounding with ties toward zero. NVFP4 uses E4M3FN block scales with nearest-even
rounding and an additional per-tensor global scale. Its lower-bit block-size-128 configuration transfers a block-size-16
calibrated mapping and is therefore identified as NVFP-style.
Mixed-bit payload implementation.
Keys and values are encoded separately with independently specified integer
transition-bit budgets, while retaining the same vector length and reconstruction format. A budget of c bits gives 2c
successors per trellis state and a payload of c/V bits per scalar element. Increasing V therefore permits finer payload
increments without changing the MX element precision. The allocation is fixed for each role across layers; it does not
introduce token-dependent or layer-dependent bit selection.

Baseline methods with MX compute formats.
We adapt NSNQuant and VecInfer by converting their reconstructed VQ

Retained costs require O(2L) memory for Viterbi. Beam search requires O(2bstart)

An efficient implementation evaluates candidate transitions in parallel (Chen et al., 2018),
