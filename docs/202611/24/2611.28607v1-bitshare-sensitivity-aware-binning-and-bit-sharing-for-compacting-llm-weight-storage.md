## 摘要
小批量规模下使用大语言模型进行解码受限于内存带宽，因此每个权重所存储的比特数在很大程度上决定了其成本。分组整数量化将一组内每个权重以相同精度存储，尽管同一组内的输入通道在敏感度上存在差异。我们提出 BITSHARE，一种无码本的权重格式，它保留分组量化的整数网格与反量化器，但在每个组内改变精度。敏感度感知分箱将每组通道按固定位置放入三个箱中，而具有最优比特值分配的静态比特共享让较不敏感的权重共享其低位，每个低位在每组中存储一次或每对权重存储一次。共享感知版本的 GPTQ 选择每个存储值，无需微调，也无需码本。BITSHARE 有两种模式。BITSHARE-U 为每个组赋予相同布局，因此其解码器通过固定布线来路由比特；BITSHARE-N 则在相同比特预算内为每个组选择布局。在 Pile 上校准并在相同存储量下，两种模式在 WikiText-2 和 C4 上于 3 比特和 2 比特时均比 GPTQ 具有更低的困惑度。在 Llama-2 和 Llama-3 模型上于 2 比特时，BITSHARE-N 将 WikiText-2 困惑度相较 SliM-LLM 最多降低 70%，相较 GPTAQ 最多降低 35%。在达到 SliM-LLM 的 2 比特困惑度时，BITSHARE-U 每个权重少存储 13.6-19.4% 的比特，并以相同比例减少 DRAM 权重流量。一个在 SkyWater 130 nm 中综合的、经过验证的硬件解码器实现，以 INT-n 和 SliM-LLM 解码器的吞吐率重建 BITSHARE 权重。

## Abstract
Decoding with large language models at small batch sizes is limited by memory bandwidth, so the bits stored per weight largely set its cost. Group-wise integer quantization stores every weight of a group at the same precision, although the input channels of a group differ in sensitivity. We present BITSHARE, a codebook-free weight format that keeps the integer grid and the dequantizer of group-wise quantization but varies precision within each group. Sensitivity-aware binning places the channels of each group into three bins at fixed positions, and static bit sharing with optimal bit-value allocation lets the less sensitive weights share their lower bits, each stored once per group or once per pair of weights. A sharing-aware version of GPTQ chooses every stored value, with no fine-tuning and no codebook. BITSHARE has two modes. BITSHARE-U gives every group the same layout, so its decoder routes bits by fixed wiring, while BITSHARE-N chooses a layout per group within the same bit budget. With calibration on the Pile and at the same storage, both modes have lower perplexity than GPTQ at 3 and 2 bits on WikiText-2 and C4. At 2 bits across Llama-2 and Llama-3 models, BITSHARE-N lowers WikiText-2 perplexity by up to 70% against SliM-LLM and up to 35% against GPTAQ. At the 2-bit perplexity of SliM-LLM, BITSHARE-U stores 13.6-19.4% fewer bits per weight, cutting DRAM weight traffic by the same fraction. A verified hardware decoder implementation synthesized in SkyWater 130 nm reconstructs BITSHARE weights at the throughput of INT-n and SliM-LLM decoders.

## 一、核心问题与研究动机

- **背景瓶颈**：小批量（batch=1）自回归解码时，每生成一个 token 都要把全部权重从 DRAM 读一遍，权重流量远超算术量，因此**每权重存储比特数（bits per weight）几乎线性决定解码速度与单卡可容纳模型规模**。
- **现有格式的共性缺陷**：主流分组整数量化（GPTQ、GPTAQ、AWQ、OmniQuant 等）把每行按 128 个输入通道分组，组内所有权重共用同一精度。但组内不同输入通道对层输出的影响（由激活能量 / Hessian 对角 `h_j` 度量）差异极大，**统一精度造成存储浪费**。
- **已有改进路线的代价**：
  - 离群值方法（OWQ、SpQR、PB-LLM）：需存储离群权重位置并引入稀疏解码路径；
  - 混合精度（SliM-LLM）：只在**组间**变精度，需每组存宽度，且报告 2 bit 下解码吞吐比 GPTQ 低 20–27%；
  - 码本/格（QuIP#、AQLM、QTIP）：放弃整数量化反量化器，依赖查表/格状解码，常需微调；
  - 逐权重位宽：每权重至少多花 1 bit 元数据，相当于 2 bit 预算的一半，不可行。
- **论文定位**：提出首个"**共享结构预先固定、共享比特值由二阶编码器（GPTQ）选择**"的 LLM 整型权重格式，在组内实现变精度且**无逐权重元数据、无码本、无微调**，同时保留 INT-n 的网格与反量化器。

## 二、方法论

### 2.1 总体思想
- 保留分组量化的重建式 `ŵ_ij = s_ig (q_ij − z_ig)`，但工作在**比目标码率细一位的网格**上：3 bit 格式用 INT4 网格（n=4），2 bit 格式用 INT3 网格（n=3）。
- 每组（layout）由两个数 `(U_g, D_g)` 描述：U 个最敏感通道进**高箱**、D 个最不敏感通道进**低箱**、其余 M = G−U−D 进**中箱**；高/中/低箱分别存 n、n−1、n−2 位（均为最高有效位），缺的低位由**共享比特**补齐。
- 分箱本质是组内通道的一个**置换 π**（每层一个，所有行共享），离线作用于 W 的列，推理时按 π 读取激活（或逆置换输出），成本约 0.0012 bit/weight（Llama-2-7B）。

### 2.2 敏感度感知分箱
- 敏感度取 GPTQ 本来就要算的 Hessian 对角：`h_j = [H]_jj`，`H = (2/N) XXᵀ`。
- 箱的位置**固定**：位置 `0..U−1` 为高箱、`U..G−D−1` 为中箱、`G−D..G−1` 为低箱，箱内保持原通道顺序。因此"某位置属于哪个箱、哪些位存/共享"只取决于位置与 `(U_g, D_g)`，解码时仅需两次比较，无需逐权重元数据。

### 2.3 静态比特共享
- 两类共享比特：
  - **flag `f_ig`**：每 group-row 一个存储位，供所有中箱与低箱权重的 `b0`；
  - **pair bit `c_igk`**：低箱位置两两配对 `(G−D+2k, G−D+2k+1)`，一对共享一个存储位作为两者的 `b1`。
- 码字构造（文字表述）：高箱 `q = v`（n 位字段）；中箱 `q = 2v + f`；低箱 `q = 4v + 2c_k + f`。
- 关键洞察：**共享是"约束"而非"丢弃"**——中箱权重可在"奇偶性为 f"的码中任取，相当于步长加倍的细网格；低箱可在模 4 同余类中任取，偏移由每对自行选择。INT3 网格上该步长仍比 INT2 细 14%。
- flag 的作用：为窄网格选定"未覆盖的一端"（奇偶 0 缺最高码、奇偶 1 缺码 0），使偏移由编码器按权重重要性选择，而非被零点奇偶性绑死（消融显示改用零点奇偶性可省 1/128 bit 但困惑度升 5–30%）。
- 位预算：`(n−1)G + δ(U,D) + n + 17`，其中 `δ = U − D/2`；参考布局 **U8 D16（M=104）使 δ=0**，恰好等于 INT-(n−1) 的载荷；最终 3.164 / 2.156 bit/weight，仅比 INT3/INT2 多 0.016。
- 更低码率可推广为 B 路共享（`δ = U − D(1−1/B)`）或直接丢弃 `b1`（`δ = U − D`）；正文两模式固定 B=2，其他变体仅用于延伸率-质量曲线。

### 2.4 BitShare 的两种模式
- **BitShare-U**：所有层所有组用同一布局（默认 U8 D16），解码为**固定布线**，不存布局索引。
- **BitShare-N**：每组从 44 个布局的菜单（U∈{0,4,8,12,16,24,32} × D∈{0,16,32,48,64,96} 及 δ=0 系列，δ∈[−48,+32]）中选一个，每组多存 6 bit 索引（≈10⁻⁵ bit/weight）。

### 2.5 逐组布局分配（BitShare-N）
- 对每组 g 与布局 ℓ，用统一的范围搜索（含 flag）测选择误差 `E_g(ℓ) = Σ_i Σ_{j∈g} h_j (w_ij − ŵ_ij^(ℓ))²`。
- 层内求解**多选背包**：`min Σ_g E_g(ℓ_g) s.t. Σ_g δ(ℓ_g) ≤ 0`（层总载荷不超过参考布局）。
- 因所有 δ 是 4 的倍数，用**动态规划**对偏移累加和精确求解，状态数 ≤ 20·C/G + 1。

### 2.6 共享感知 GPTQ（编码器）
在标准 GPTQ 流程上改三处（逐层、逐列、Hessian 误差补偿不变）：
1. **组参数在格式内搜索**：列循环前，对 `p ∈ {1.00,0.98,…,0.80}` 与 `f ∈ {0,1}` 联合搜索，每组每行按"该箱允许的最近码"取整、每对取误差更小的 pair bit，保留敏感度加权误差最小者（搜索量翻倍）。
2. **按敏感度排序的量化单元**：高/中箱为单列，低箱为列对；全层按 `h_j` 递减（act-order）量化，列对按更敏感的列排序，使最敏感通道先量化、后续列最多。
3. **共享比特由 GPTQ 目标决定**：列对的两个 `c` 值都试，第一列按 `b1=c` 取整并把误差传播到第二列后再取整第二列，比较目标 `Σ(w−ŵ)²/d_j²`（`d_j` 为 `(H+λI)⁻¹` 的 Cholesky 对角，λ=0.01·h）取更优者，再向剩余列传播误差。

### 2.7 存储格式与解码器
- group-row 字段顺序：`s`(FP16) → `z`(n bit) → `f`(1 bit) → 按位置排列的 n / n−1 / n−2 位字段 → D/2 个 pair bit；无填充、按位紧密打包。
- 解码：两次比较定箱 → 按 Eq.2 拼码（纯布线，无算术）→ 与 INT-n 完全相同的反量化（一次 round-to-nearest-even 到 binary16）。
- BitShare-N 需查 44 项布局 ROM，并用层内布局索引前缀和定位 group-row；同层所有行的布局序列相同。
