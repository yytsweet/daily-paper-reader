# Best-of-N Test-Time Steering Can Lead to Reward Hacking in Vision-Language-Action Models 

Vanshaj Khattar 1, Jing Liu 2, Toshiaki Koike-Akino 2, Ming Jin 1, Ye Wang 2

> 1

Virginia Tech, 2Mitsubishi Electric Research Laboratories 

Abstract 

Vision-language-action (VLA) models have shown promise for general-purpose robotic manipulation, but adapting to changing environmental conditions still remains challenging. Recent test-time steering methods have shown promise in enabling adaptive VLA policies by utilizing additional computation during deployment. In this paper, we consider best-of-N test-time steering for VLA models, where multiple action candidates are sampled from a fixed policy and a verifier is used to select the best one during deployment. We show that increasing 

N does not always improve performance when the verifier is inaccurate, and can favor candidates whose scores exploit prediction errors, a form of reward hacking. We study this effect on 60 LIBERO-Safety task-level cases using a π0.5 policy, with ten repetitions per case. We introduce controlled errors in a MuJoCo trajectory verifier and show that as N increases, selected candidate rewards diverge from the accurate verifier rewards, leading to reward hacking. We also show that verifier calibration and softmax-based candidate selection can mitigate reward hacking in some settings. 

1 Introduction 

Vision-language-action (VLA) models map visual observations and language instructions to robot actions and have shown broad manipulation capabilities [Brohan et al., 2023, Kim et al., 2024, Physical Intelligence et al., 2025]. However, their performance can deteriorate when deployment conditions differ from those seen during training [Fei et al., 2025]. There are two ways to improve the generalization capabilities of VLAs. The first is to collect additional demonstrations and retrain or fine-tune the policy; however, this can be computationally expensive [Lu et al., 2025, Kim et al., 2025]. Another widely used and less computationally expensive approach is test-time steering, where additional computation during execution is used to steer the VLA actions [Nakamoto et al., 2024, Dai et al., 2025] or select the best one from a few sampled candidates [Kwok et al., 2025, Zhang and Shah, 2026]. Recent test-time steering methods such as RoboMonkey and VERITAS have shown promising results with best-of-N (BoN) test-time steering, which samples multiple action candidates and uses a verifier to select the best one for execution [Kwok et al., 2025, Zhang and Shah, 2026]. However, its benefit depends on the verifier’s ability to rank those candidates. In practice, perception errors, inaccurate predictions of physical motion, or an imperfect scoring rule can cause a poor action to receive a high score. This problem has been identified in large language models (LLMs), where a reward model or verifier is used to pick the best of several sampled responses. Gao et al. [2023] showed that when best-of-N

selection uses an imperfect reward model, the true quality of the selected response first improves and then drops as N grows. Similar effects have been shown when selecting solutions to math problems with a learned verifier Cobbe et al. [2021] and when selecting code with unit tests Stroebl et al. [2026], where wrong answers that pass the check limit the benefit of more samples. Recent work explains this

Similar effects have recently been reported in robotics literature. Luo et al. [2026] showed that optimizing robot policies against a learned visual critic can increase failures in which the robot acts on the wrong object, because the critic scores some of these failures above real successes. Bakshi and Bose [2026] showed that sampling-based planning with rewards learned from human preferences can reduce the true task return by up to 76%, and that best-of-N selection with such a reward can perform worse than taking a single action. A recent survey of verifiers for robot policies notes that how far a policy can be optimized against a verifier before its score stops tracking the task is still largely unexplored [Wan et al., 2026]. These studies use learned scores and focus on task success. In contrast, we use a MuJoCo simulator whose errors we control, and a proxy reward function. We measure both safety violations and task completion. This raises the central question of our study: when the verifier is imperfect, does additional search still improve robot behavior, or can it reduce task performance and safety? We study this question on the LIBERO-Safety benchmark Cui et al. [2026], which requires robots to complete manipulation tasks while following constraints on how objects are grasped and avoiding contact with nearby obstacles and simulated human hands. In these tasks, task progress and safety can conflict: an action can move an object toward its goal while violating a safety constraint. We keep the VLA policy and the execution environment fixed, and add controlled errors only inside the verifier, either by adding noise to the predicted object positions or by changing the simulated dynamics. For each selected action, we compare the proxy score from the perturbed verifier with its clean score from the unperturbed simulator. 3.2 RQ2: What leads to reward hacking in best-of-N steering? 

An unsafe action can be selected in two ways. In an accepted unsafe choice , the verifier predicts the violation but still selects the action because its task score outweighs the safety penalty. In a missed unsafe choice , the verifier predicts no violation, but the action violates a constraint when evaluated in the unperturbed simulator. The first case comes from how safety and task progress are weighted and can occur even with a perfect verifier; the second comes from prediction errors and is the form of reward hacking we study. These choices also recur within episodes: the number of episodes with at least two missed unsafe choices rises with N for all three error types (Figure 4C). Larger N therefore increasingly selects unsafe actions that the verifier believes are safe, which no rule based on the verifier’s own predictions can filter out. 3.3 RQ3: Can we mitigate reward hacking? 

RQ2 showed that, as N grows, selection increasingly favors candidates whose predicted scores are too optimistic. This suggests two ways to reduce reward hacking: first, rely less on the single highest score, and second, change how the safety and task scores are combined. Both ideas have been used to mitigate inference-time reward hacking in LLMs Khalaf et al. [2025], Wang et al. [2026], and we test each with N = 75 fixed. 

3.3.1 Soft best-of-N

Best-of-N always takes the top-scoring candidate, and as N grows, the top score is increasingly likely to belong to a candidate whose score is overestimated. Soft selection hedges against this by spreading probability over several high-scoring candidates, so no single overestimated score decides the choice. No single β is best for both metrics under every error type, so soft selection offers a modest mitigation. 

3.3.2 Shared-weight calibration 

Soft selection does not change how the scores are combined. If verifier errors affect the safety and task scores differently, changing their weights can reduce the influence of the less reliable score. Following SLOP [Wang et al., 2026], we fit one pair of weights (wS , w T ) for each verifier error, shared across tasks, to maximize the expected clean reward of the selected candidate on saved states from N = 75 rollouts (Appendix E). For dynamics errors, fitting uses three cases that are excluded from evaluation, leaving 57 held-out cases; for output noise, fitting uses all 60 evaluation cases. The calibrated weights enter the softmax without the σc scaling, so at β = 16 their selection sharpness also differs from the original-weight setting in Section 3.3.1. For human safety L2 tasks with over-responsive dynamics, best-of-N loses its gains at large N :from N = 30 to 75 , safe completion falls from 82% to 70% and violations rise from 10% to 18% 

(Figure 6). With calibrated weights, safe completion instead rises from 80% to 86% and violations fall from 6% to 4% . 4 Conclusion and Future Work 

In this paper, we show that best-of-N test-time steering of VLA policies is vulnerable to inference-time reward hacking when the verifier is imperfect. With a perfect verifier, increasing N improves safe task completion, but with controlled errors in the verifier’s simulation, larger N widens the gap between predicted and clean reward and can erase these gains while increasing safety violations. Our decision-level analysis explains why safety filtering alone does not prevent this: as N grows, the selected unsafe actions are increasingly ones the verifier predicts to be safe. Soft best-of-N sampling and calibrated weights reduce this failure in some conditions, but neither is effective across all verifier errors. Future work should test these effects on real robots, with other policies and learned verifiers, and under error types not studied here. 8References

With a perfect verifier, safe task completion rises from 43 .8% at N = 1

More candidates thus raise the predicted reward without the gains in safe completion and safety seen with the perfect verifier. 

Further reward evidence. For obstacle avoidance L0 with output noise, increasing N from 30 to 75 raises the mean predicted reward of the selected action from 0.1823 to 0.2023 , while its clean reward falls slightly, from 0.0229 to 0.0217 . Over the same range, safe completion falls from 32% to 

20% (16 to 10 of 50 episodes), and violations rise from 14% to 18% (7 to 9). In the two over-response groups in Figure 2, by contrast, the mean predicted reward itself falls from N = 30 to 75 , so their drop in outcomes is not by itself a case of predicted reward rising while clean reward falls. These reward means are averaged over the states reached at each N , not over a fixed set of states.

We use saved records from the 40 cases at levels L0–L1, with ten repetitions per case and the original weights wS = wT = 0 .5. A selected action is unsafe if it violates any constraint during its five control steps in the unperturbed simulator, and it is a missed unsafe choice if the imperfect verifier predicted no violations. 

Output noise (Figure 4A). For output noise, every candidate was also evaluated in the unperturbed simulator. At each decision in episodes run with weighted selection at N = 75 , we apply safety-first selection to the first N candidates, for N ∈ { 5, 10 , 30 , 50 , 75 }. Safety-first selection removes candidates with any predicted violation and then maximizes ˆTi; ties go to the earliest candidate. If no candidate is predicted safe, it selects no action; this happens at 268, 68, 3, 0, and 0 decisions for the five values of N . We exclude these decisions from the counts, and we did not evaluate whether stopping there would be safe. Because the decisions come from weighted selection, this analysis does not show which states a closed-loop safety-first controller would reach. 

Dynamics errors (Figure 4B). For dynamics errors, only the action chosen by weighted selection was evaluated in the unperturbed simulator, so we count missed unsafe choices among those actions in the episodes run at each N . The number of decisions varies by less than 1% across N , so the counts can be compared directly. Safety-first selection would choose the same action at each of these decisions, but this does not show that it would be safe in closed loop. 

Repeated missed choices (Figure 4C). We count episodes with at least two decisions whose selected action is a missed unsafe choice; each condition and N has 400 episodes.
