# RMR-VLA: Recurrent Memory Reasoning for Vision-Language-Action Models 

Yiheng Du 1,* Jingqi Tian 2,* Xu Jiang 1,* Jiexuan Zhang 1

Shuyu Wang 1 Zecheng Tang 1 Jian Zhang 11Peking University 2Tsinghua University 

Abstract 

Long-horizon, history-dependent robotic manipulation often requires acting on visual cues that have disappeared, such as an object indicated earlier or a target hidden under a moving cup. The key challenge is to maintain what past evidence means for the next action as the scene changes. We introduce Recurrent Memory Reasoning (RMR), an explicit reasoning step that connects memory to action inside a vision-language-action model (VLA), with no external reasoning model. At each update, the VLA first infers an event from visual evidence, then revises the task state and grounds a subgoal in the current scene to guide action generation. Carrying the state and subgoal across updates lets remembered identities and task progress determine the current target, doubling RoboMME success over an otherwise identical model without recurrence. Joint training lets one VLA both reason and act; because its memory decisions are text tokens with exact likelihoods, GRPO refines them from rollout rewards without making action generation stochastic. Among the compared methods, RMR-VLA achieves the best results on RoboMME (66.46% overall, 79.83% on the Reference category) and LIBERO-Mem (90.08%). Maintain Update Ground Execute

1arXiv:2611.30145v1 [cs.CV] 23 Nov 2026 1 Introduction 

The visual evidence that determines a robot’s next action can disappear before the robot is ready to act. Consider a red cube hidden under a cup that then trades places with another cup. Choosing which cup to lift requires linking red to the cup that now hides it. Similar demands arise when an indicated object loses its highlight or when a repeated manipulation returns the scene to a familiar configuration. In such long-horizon, history-dependent robotic manipulation [6, 7], the next action depends on task information that the current image does not reveal. Memory-augmented vision-language-action models (VLAs) retain temporal context through sampled or compressed visual representations or through language records [7, 16, 27, 29, 31, 37, 40, 44], while agentic systems reason over history with external models [5, 26, 28]. When visual histories or latent memories feed action prediction directly, the policy must infer from the accumulated context how object associations and task progress have changed. Language records make spatial context, plans, and attempted or completed subtasks explicit [16, 29], yet the policy must still resolve these entries against the changed scene. Both leave the policy to work out, while acting, what past information implies now; agentic systems reason about it explicitly, but in an external model. What must be carried across decisions is twofold: the task state, since an object association can stay relevant across many actions, and the operation under way, since its completion advances progress and changes the next target. We introduce Recurrent Memory Reasoning (RMR), which turns each memory update into explicit reasoning inside the VLA. At each update, its vision-language model (VLM) writes one reasoning trace: from observed evidence it infers an event , revises the task state , and grounds the next subgoal in it. The state and subgoal feed the next update, and the subgoal guides the next actions. In Fig. 1, the cups hiding red and blue swap while the robot presses a button; the trace records the swap and red’s new location, and once the button is pressed, the VLM reasons that the next subgoal is to lift the cup now hiding red. Each update thus reasons out what past information implies now, before the robot acts. RMR reasons within the VLA, with no external reasoning model. We build RMR-VLA on π0.5 [32], whose VLM already predicts a semantic subtask that conditions its action expert; in RMR-VLA, this subtask becomes the subgoal reasoned out by the memory update. The central difficulty is that the VLM must serve two roles, writing the reasoning trace and encoding inputs for the action expert, and training them one after the other weakens one of them. We therefore train trace generation and action prediction jointly, then freeze the VLM and fine-tune the action expert. Since the deployed model reads the state it wrote itself, we refine the model by reinforcement learning (RL) on its own rollouts. Flow-based VLAs such as π0.5 give no tractable action likelihood, so πRL recasts their action generation as a stochastic process before applying RL [4]. RMR-VLA makes its memory decisions in text with exact token likelihoods, so group relative policy optimization (GRPO) [12, 33] optimizes the reasoning trace directly while the action expert stays frozen. RMR-VLA is strongest where earlier observations determine later targets, setting the best results among the compared methods on the RoboMME Reference tasks [7] (79.83%) and on LIBERO-Mem [6] (90.08%). Across all RoboMME tasks, its 66.46% is the best result among the compared methods, including systems with an external reasoning model. Carrying the state and subgoal forward doubles success over an otherwise identical model without recurrence, and among the trace fields the maintained state brings the largest gain, doubling the correctness of subgoals that act on earlier cues. Our contributions are threefold: • Recurrent memory reasoning. Each memory update is an explicit reasoning chain from visual evidence through events and a maintained task state to a grounded subgoal, revising what changes and preserving what still holds. • Memory reasoning and control in one VLA. # 2 Related Work 

Retaining and compressing visual history. Memory policies keep past observations through frame sampling [7], token selection [44], feature memory banks [9, 34], gated attention over cached tokens [11], or, for long videos, adaptive memory management [20, 50]. Within each step, token pruning guided by semantic attention compresses a VLA’s visual input for efficient manipulation [30]. LTM-π encodes visual transitions [37] and ActMem-VLA encodes executed actions [48]; other policies store episodic tokens, fast weights, object slots, or recurrent and retrieved visual streams [6, 15, 19, 27, 40]. These representations supply temporal context for action prediction; RMR-VLA turns it into an explicit task state and a grounded subgoal. 

Embodied reasoning before action. ECoT predicts plans, subtasks, motion descriptions, and spatial features before action prediction [45], and π0.5 predicts a semantic subtask for its action expert [32]; other policies keep language records of plans, subtasks, or events across steps [16, 29, 31]. RMR-VLA makes the subtask the result of recurrent memory reasoning: the current state resolves which target to act on, and the subgoal supplies it to control. 3Memory and planning with external models. GAMMA coordinates external memory and reasoning agents [28], MemER retrieves keyframes for an external VLM that instructs a low-level policy [36], and HeLM and 2AM steer low-level action models with external commands, task memory, or 2D hints [18, 22]; PAL and PonderPounce add planning or context models [5, 26]. LoopVLA stores completed subtasks as event memory, segmented by online Qwen3-VL-4B subgoals [49]. RMR-VLA learns memory reasoning and control in its shared VLM and action expert. 

Reasoning in multimodal models. Explicit reasoning also strengthens multimodal models beyond manip-ulation: AdaThinkV adapts its thinking for token-efficient video reasoning [39], Context-CoT synthesizes high-quality reasoning to enhance context learning [21], OP-CAD distills on-policy from clean audio for robust audio-visual reasoning [35], and Ponder & Press advances visual GUI agents toward general computer control [41]. Other multimodal models align disentangled audio semantics with visual features for audio-visual segmentation [38] or keep style aligned across generated images [46]. RMR-VLA brings explicit reasoning into the memory of a VLA and refines the resulting trace with GRPO. 

# 3 Recurrent Memory Reasoning 

RMR-VLA maintains a current task state so that earlier visual cues continue to determine the robot’s next target after they leave view (Fig. 2). At each update, the VLM interprets new evidence, revises this state, and grounds the next subgoal; the action expert executes the subgoal, and the resulting observations feed the next update. 

3.1 Recurrent Memory Interface 

Let t index memory updates, q denote the task instruction, ot the current observation, comprising the camera views and the robot’s proprioception, and Ht the visual history, a bounded window of past frames, each pooled into a few visual tokens as in [3, 7] (Appendix A). RMR-VLA keeps the π0.5 architecture, a VLM with parameters θ and an action expert with parameters ϕ; we write Fθ for the VLM and Fθ,ϕ for the full model. Each memory update consists of a write pass and an act pass. 

Write pass. The VLM reads these inputs together with the recurrent pair (st−1, g t−1) and generates the 

trace 

ct = Fθ(q, o t, H t, s t−1, g t−1) = [ et, v t, s t, g t], (1) whose fields are the observation evidence et, the typed event vt, the maintained state st, and the grounded subgoal gt, produced as one autoregressive text output. 

Act pass. The full model then predicts a continuous action chunk by flow matching [2, 25], conditioned on the subgoal just written: 

at = Fθ,ϕ (q, o t, g t). (2) The VLM encodes these inputs for the action expert. 

The subgoal carries memory to control. The act pass conditions on the present inputs and gt, while the visual history and the maintained state remain in the write pass. Everything control needs from the past therefore reaches it through the subgoal. The subgoal resolves which object to act on, such as the cup that now hides red, and guides the action expert’s execution. 3.2 Reasoning over the Current State 

Each write must leave behind a state that is still true after the scene has changed and hand the action expert a target it can act on now. The trace does both with four fields written in the order in which they depend on one another (Table 1): the VLM commits to what it saw before it edits the state, and updates the state before it chooses a subgoal. 

The state changes only when the scene gives a reason. The observation evidence et reports motion, contact, and completion cues. The typed event vt identifies a change such as covering, swapping, highlighting, or arrival at a target, with none when no such event occurs. The maintained state st lists task progress and the image location of each task-relevant object under that object’s identity. The VLM revises st−1 using both evidence and events: an event updates the affected identity–location associations or arrival count, completion evidence advances task progress, and unaffected entries carry over. Completion cues can therefore advance progress while vt is none . A cube that disappears under a cup stays in the state as red , at a location that follows its cup, and a cue shown once, such as the order of demonstrated placements, stays in the state after it has left the visual history. 

The subgoal turns the state into a target. The grounded subgoal gt resolves the instruction against the updated state, naming the operation, the image location of its target, and the condition that completes it. The location is read from the state, so the action expert receives a spatially explicit target after the cue that singled it out has left view. The completion condition serves the next write: with gt−1 in its input, the VLM knows which operation is under way and what evidence finishes it. 

Seen early, used late. In Fig. 1, the red and blue cups trade places while the robot is pressing a button: the event moves red and blue in the state, while the subgoal is still to press the left button. Four updates later, the button is pressed, and the new subgoal lifts the cup at the location the state now records for red (Table 1, bold). The swap entered memory when it was seen and reached control when it was needed; the recurrent state carried it across the updates in between.

3.4 Learning from Rollouts 

Training on rollouts exposes the model to observations arising from its own decisions. Flow matching gives no tractable action likelihood, so ReinFlow and πRL first make action generation stochastic by injecting noise into its denoising steps [4, 47]. In RMR-VLA, the decisions that carry memory to control are trace tokens with exact likelihoods. Starting from the supervised model, we therefore apply GRPO [12, 33] directly to the 6generated trace, updating VLM LoRA [17] while freezing the action expert and its flow-matching sampler. # 4 Experiments 

We compare RMR-VLA with existing memory methods on long-horizon, history-dependent robotic manipu-lation (Secs. 4.2 and 4.3), trace its gains to the trace fields and their recurrence (Sec. 4.4), and examine how a single VLA learns to write the trace and act on it (Secs. 4.5 and 4.6). 

4.1 Evaluation Setup 

Benchmark and training data. RoboMME contains 16 tasks in four categories of four [7]: Counting tracks repeated operations, Permanence tracks objects through occlusion and swaps, Reference requires acting on an earlier observation, and Imitation requires reproducing a demonstration. Supervised training uses the official demonstrations, which we also annotate with trace labels. At evaluation, the model maintains its own state and generates its own subgoals. We also train and evaluate on LIBERO-Mem [6], whose ten tasks require remembering an object’s last motion, how many times an operation has been repeated, how identical bowls have been rearranged, and which of two identical baskets holds an object (Appendix C). 

Metrics. Following the official protocols, we evaluate 50 episodes per task on RoboMME and 40 on LIBERO-Mem, averaging success over tasks and three evaluation seeds. 

4.2 Acting on Past Evidence 

Earlier cues decide later targets. In the four Reference tasks, an earlier observation determines the target of a later action. RMR-VLA + GRPO reaches 79.83% on them, the highest Reference average among the compared methods, including systems with an external reasoning model (Table 2). The margin is widest on VideoPlaceOrder, whose targets follow the order of demonstrated placements: RMR-VLA + GRPO reaches 90.67%, against 39.56% for the strongest published policy without an external reasoning model. Overall success in a single VLA. Across all 16 tasks, RMR-VLA + GRPO reaches 66.46%, the best overall result among the compared methods: 7.92 points above the best method without an external reasoning model, LTM-π [37] (DreamDojo [10]), and above the best system with one, GAMMA with a 9B agent (66.0%). 

Where the trace helps less. RMR-VLA trails the strongest memory policies on StopCube (6.00%, against 100% for LTM-π), which requires pressing a button at the moment a moving cube reaches its target on a specified pass. The cube passes the target between updates, so the press must land within one action chunk, a timing precision that the trace does not control. 

4.3 Object Memory on LIBERO-Mem 

On LIBERO-Mem (Table 3), supervised RMR-VLA reaches 89.17% and GRPO raises it to 90.08%; the best published results, ActMem-VLA (80.8%) and LTM-π (DreamDojo, 80.5%), trail the supervised model by over eight points. 

Success holds as bowl returns accumulate. Across the bowl-return tasks requiring one, three, five, and seven returns, RMR-VLA + GRPO stays at or above 97.50% (Fig. 3), while no policy without an external reasoning model reports over 75.6% at seven returns. Each completed return advances a count in the state, so the seventh return poses the same update as the first; in Fig. 5b, near-identical views carry different counts, and the count decides whether the next subgoal picks up again or ends the task. 

Tracking identical objects. The two relation tasks rearrange visually identical bowls, the demand illustrated by the cup swap in Fig. 1. RMR-VLA + GRPO obtains the highest reported score for rotating three bowls (63.33%), and supervised RMR-VLA reaches 72.50% for swapping two, second only to LTM-π (CD-LAM [42], 80.0%; Table 3). 4.5 Training Schedules 

Training the roles in sequence loses one of them. Under the same number of training steps and without GRPO (Table 5), sequential training optimizes the trace loss, then the action loss. If the action stage also updates the VLM, the model loses the trace it acts on: task success falls to 8.29%, and rises to 47.04% when separate models generate traces and actions, at the cost of running two models. With a frozen VLM, the trace survives, but the action expert uses a representation never shaped by control (27.50%). 

Joint training keeps both; fine-tuning the action expert sharpens control. Optimizing both losses throughout reaches 54.88% with a single model, above the two-model pipeline. Ending with action-expert fine-tuning instead, with the VLM frozen, raises success to 59.71% with gains in all four categories: once joint training has settled what the VLM writes and represents, the action expert refines control on a fixed interface. This schedule is the best of the seven in every category (Appendix C).

πRL-style training [4], which updates only the action expert with terminal reward, lowers success from 59.71% to 54.38%. GRPO on the generated traces, with the action expert frozen, instead raises it to 61.38% with terminal reward alone and to 66.46% with subgoal correctness m added (Table 6), the latter improving all four category averages and 11 of the 16 tasks. # 5 Conclusion 

RMR lets a vision-language-action model remember by reasoning. Before each action chunk, the VLA writes a text trace: it revises an explicit task state from new evidence and grounds the subgoal its action expert executes, so a cue enters memory when it is seen and reaches control when it is needed. Carrying the state and subgoal forward doubles RoboMME success over an otherwise identical model without recurrence, and among the trace fields the state brings the largest gain in subgoal correctness. Joint training keeps reasoning and control in one VLA, and GRPO refines the text trace from rollout rewards with the action expert frozen. By writing, revising, and acting on its own memory, RMR-VLA achieves the best RoboMME and LIBERO-Mem results among the compared methods.

16 A Method and Training Details 

A.1 Inputs and Update Schedule 

Every 16 frames, the write pass reads the instruction, the current camera views and proprioception, the visual history, and the preceding state and subgoal (st−1, g t−1). The visual history covers the preceding 32 frames. Following FrameSamp in RoboMME [7] and VideoLLM-online [3], we pool each frame into 16 visual tokens, for a total of 512. The state and subgoal carry information beyond this window as text. In the act pass, the shared VLM encodes the instruction, current observation, and the operation and target specified by the new subgoal. The robot executes 16 steps of the predicted action chunk before the next update. The completion condition stays in the recurrent subgoal so that the next write pass can recognize when the operation is complete. On RoboMME tasks with a demonstration video, the write pass runs at the same interval during playback and writes the subgoal watch . At the first update after playback, the VLM uses the maintained state to identify the target for the first act pass (Fig. 8). On LIBERO-Mem, each task begins with robot interaction, and an act pass follows every write pass. 

Update interval and visual history. Table 7 compares the update interval and the number of frames available to each write pass. At intervals of 4, 8, and 16 frames, extending the history from one interval to two raises overall RoboMME success from 44.00% to 45.79%, from 43.29% to 49.63%, and from 57.96% to 59.71%, respectively. With two intervals of history, the write pass sees frames on both sides of the preceding update. For a fixed 32-frame history, shortening the interval from 32 to 16 frames lets the model revise its subgoal after 16 executed steps and raises success from 54.17% to 59.71%. 

A.2 Trace Labels 

At each update of a training demonstration, annotation rules use the simulator’s object states and task progress up to that point to label the four trace fields in generation order. • Observation evidence et reports contact and motion since the preceding update ( grasped , moving ,

released ), completion of the preceding subgoal ( done: ), or a demonstrated step ( shown: ). When the field reports none of these cues, its label is still .• Typed event vt names a change from a fixed vocabulary, such as covering, swapping, highlighting, or arrival at a target. An occurrence index ( #n ) distinguishes repeated events. The label names an event once its completion is visible and reads none otherwise. • Maintained state st carries forward object identities, locations, and task progress. An event updates the affected identity–location associations or arrival count. Completion evidence advances the step counter (step k) and the relevant progress counts. Other entries carry over. The rules update an object’s location when it is held or moves more than about 2 cm from its previous resting position. Selective token weighting. In Ltrace , tokens copied from the preceding state or subgoal and formatting tokens receive weight wt,i = 1 /3. Tokens for new events, state updates, subgoal switches, and the end of the trace receive wt,i = 1 . This weighting draws on SOM-DST [23], which generates new values for dialogue-state slots that change between turns. Here, the VLM learns to generate the full trace, with greater weight on the changes. 

Recoverable-history perturbations. During evaluation and GRPO rollouts, the write pass reads the VLM’s own preceding state and subgoal. Copycat [43] shows how access to observation histories can lead a policy to repeat its previous action. A similar shortcut is available when the write pass can copy its preceding state or subgoal. In approximately 20% of supervised training examples, we perturb one entry in the preceding state or replace the preceding subgoal, keeping the annotated target trace fixed. A state perturbation shifts coordinates by approximately 10–30 pixels per axis, removes an entry, or changes an object’s held status. A replacement subgoal comes from the same episode. We perturb only values that the write-pass inputs can recover. For example, the identity of a cube hidden under a cup is preserved when the visual history no longer shows which cube was covered.

# B GRPO Post-Training 

Starting from supervised RMR-VLA, we apply GRPO [12, 33] to the generated traces. We train rank-32 LoRA adapters [17] in the VLM at a learning rate of 3 × 10 −4, keeping the supervised base weights, visual encoder, and action expert frozen. For each task layout, we sample K = 8 episodes. An episode’s advantage is its reward minus the mean reward of the other K − 1 episodes (Eq. (7)) [1, 24]. A KL constraint of 0.1 regularizes the policy updates. 

Episode reward. The episode reward combines the terminal outcome and subgoal correctness as R =

rterm + βm (Eq. (5)). The terminal reward rterm is +1 for success and −1 for failure or timeout. Each act pass contributes one subgoal decision, and m is the fraction of decisions in the episode that match their labels. For the text comparison, we remove coordinates and the completion condition from both the generated subgoal and the label, then compare the remaining text in lowercase. C.2 Evaluation and Subgoal Diagnostics 

For each of three evaluation seeds, we run 50 episodes per RoboMME task and 40 per LIBERO-Mem task, following the official protocols. A task’s success rate is the fraction of successful episodes pooled across the three seeds. Each RoboMME category averages its four task scores. Overall success gives equal weight to every task in the benchmark. We compute differences before rounding. The supervised RMR-VLA model is the common reference for the trace, training schedule, update interval, and trace-loss weight comparisons. 

Subgoal diagnostics. Table 4 measures whether each generated subgoal specifies the decision required by its task category. • Count/stop (Counting). At each decision, we compare the subgoal and label using text alone to check the repetition index and when to stop. • Container (Permanence). We score the first cup selection in each episode. A selection is correct when both the named target identity and the cup location match the label. • Cue target (Reference). We score decisions that select a highlighted or demonstrated cube, or place a cube at a demonstrated target. Both the subgoal text and the target location must match the label. Only episodes that reach an eligible decision contribute. • Demo step (Imitation). At each decision, we compare the subgoal and label using text alone to check whether the action follows the demonstrated sequence, including direction, route, and tool use. 

Overall subgoal correctness. For each episode, m is the fraction of all subgoal decisions that match their labels under the GRPO reward criterion (Appendix B). BinFill pickup decisions use text alone because any cube of the required color is a valid target.
