# Native Block-Quantized Matrix Multiplication and Explicit K/V Residency with Dual-View Access for LLM Inference on RISC-V Vector Processors 

Weiying Wang, Yuanyang Xiang and Zhiwei Zhang 

Institute of Automation, Chinese Academy of Sciences School of Artificial Intelligence, University of Chinese Academy of Sciences Beijing 100049, China Email: {wangweiying2021,xiangyuanyang2020,zhiwei.zhang }@ia.ac.cn 

Abstract —Some key execution states in large language model inference persist across multiple instructions and are difficult to express and exploit within RVV semantics centered on individual operations. We define specialization boundaries according to data-state lifetimes and propose Quantized Block Streams (QBS) and Attention/KV Context (AKV) while preserving RVV programma-bility. QBS organizes native-block format processing, block traver-sal, integer computation, and ordered FP32 accumulation into a unified execution process, whereas AKV maintains local K/V residency and supplies operand views aligned with the computa-tion direction while leaving Attention arithmetic on RVV. Cycle-accurate RTL evaluation shows that QBS achieves geometric-mean speedups of 35.68 × and 51.34 × for projection Compute and 

Matmul , respectively, while AKV achieves a 1.45 × geometric-mean speedup over Tiled RVV for Decode Attention. Compared with the baseline, the complete design increases total area by 12.65%; on the evaluated projection workloads, throughput per area and energy efficiency improve by 46.63 × and 19.78 ×, respectively. Fur-ther evaluation demonstrates applicability across multiple block-quantization formats and across models with different Attention organizations. 

Index Terms —RISC-V Vector Extension, LLM inference, block quantization, quantized matrix multiplication, K/V reuse 

I. I NTRODUCTION 

Large language models (LLMs) are widely used in language understanding, content generation, and code processing [1]– [3], placing increasing demands on inference efficiency. Trans-former inference repeatedly executes linear projections and attention operations [4]; as model sizes and context lengths con-tinue to grow, the costs of weight access, attention computation, and intermediate-data movement become increasingly signifi-cant, making inference efficiency dependent on both computa-tional throughput and data-supply efficiency. The RISC-V Vec-tor Extension (RVV) provides vector-length-agnostic computa-tion and memory operations, offering a unified programmable execution substrate across different hardware implementations and tensor shapes [5]. However, runtime-known data layouts, reuse relationships, and state lifetimes are still largely managed by software through low-level vector operations, making it difficult for hardware to directly exploit data-organization and reuse patterns that persist across instructions. Based on this observation, we preserve RVV programmability while defining specialization boundaries according to LLM workload structure and optimizing the corresponding critical execution stages. Inference runtimes such as llama.cpp employ block quan-tization to reduce model-weight storage and bandwidth require-ments [6], but compact representation does not directly translate into efficient vector execution. In addition to low-bit values, block-quantized weights contain scales, subgroup metadata, and format-specific correction rules, requiring RVV kernels to explicitly perform parsing, integer computation, correction, floating-point updates, and block traversal. Prior work opti-mizes quantized projection at different execution boundaries, including matrix-level execution, block-scaled dot products, and native quantized-block processing [7]–[11]; however, native block-quantized projection still requires format parsing, block traversal, and output accumulation to be coordinated with matrix-level reuse. Attention presents a different data-supply problem: K/V data are generated at runtime and repeatedly reused by subsequent queries, while grouped-query attention (GQA) and Prefill further enlarge their reuse scope [12]. Although methods such as FlashAttention reduce external data movement through tiling and online Softmax [13], local K/V residency organization and operand supply matched to the com-putation direction still require explicit software orchestration on vector processors. Although these two bottlenecks arise from different execu-tion paths, they share a common property: the lifetimes of key data states extend beyond what a single RVV instruction can express. As shown in Fig. 1, quantized projection must preserve and update output accumulation state across successive K blocks, whereas attention must reuse K/V across queries and form different operand views according to the computation direction. Building on this observation, we propose Quantized Block Streams (QBS) and an Attention/KV Context (AKV). QBS defines a unified execution boundary spanning native quantized blocks to completed result tiles, bringing format handling, block traversal, and ordered accumulation across K blocks into the same execution process; AKV instead confines specialization to local K/V residency and operand supply, providing operand views matched to the computation direction. Attention arithmetic and other operations outside the supported arXiv:2611.31937v1 [cs.AR] 24 Nov 2026 scope continue to execute on standard RVV. B. Specialization Boundaries in Prior Work 

Prior work on quantized projection and Attention explores specialization across computation granularity, data representa-tion, execution mapping, and storage management [14]–[16]. For quantized projection, MX, VMXDOTP, and SpacemiT IME extend low-precision computation at the matrix, microscaling-dot-product, and tile levels, while F-BFQ and DECA combine native-format processing or near-core weight expansion with specialized matrix execution [7]–[11]. For Attention, FlashAt-tention and its successors primarily optimize tiling, online Softmax, and vector mapping [13], [17]–[20], whereas KIVI, PagedAttention, and PLENA reduce overhead through K/V rep-resentation, cache management, and on-chip data organization with dedicated execution support [21]–[23]. This work instead defines specialization boundaries from the common property of cross-instruction state lifetimes. QBS brings the path from native-block access to completed result-tile commit into a single specialized execution, jointly performing format parsing and correction, block traversal, and ordered accumulation across K blocks; AKV confines specialization to local K/V residency and operand-view supply, while Attention arithmetic remains on standard RVV. The two mechanisms exploit output-accumulation state across K blocks and K/V state across queries, respectively, leveraging cross-instruction state lifetimes and reuse relationships while preserving RVV programmability. A. QBS: Native Quantized-Block Execution Interface 

For Y = AW T, one QBS command processes M activation rows and N outputs, traverses a specified number of native quantized blocks along the K dimension, and retains the output accumulation state until the reduction completes. The QBS de-scriptor specifies the weight address, profile, layout, N , and the number of K blocks, while the command additionally specifies the activation address, M , and the destination register. When 

M or N exceeds the command range, the runtime generates multiple output tiles along the corresponding dimension; when the number of K blocks exceeds the limit, split-K is used, with each K segment independently accumulated and rounded by a QBS command before software combines the partial results, so the combined result is not required to be bitwise identical to an unsplit execution. When multiple output tiles share the same quantized acti-vations, software can explicitly manage an activation snapshot through FILL, REUSE, and RELEASE. For Q8 K activations satisfying the snapshot constraints, FILL saves the activation data read by the current command, REUSE makes the snapshot available to subsequent commands, and RELEASE frees it after the final successful use. The snapshot stores only already-quantized data, while F32-to-Q8 K quantization remains a software responsibility; reuse is explicitly specified by software rather than inferred from the source address and changes only the cross-command data-supply path without altering the block-level computation or rounding rules of QBS. 

B. AKV: K/V Context and View Interface 

Unlike QBS, which maintains output accumulation state within a command, AKV maintains K/V residency that can be reused across instructions through an explicit Attention context whose lifetime is managed using Fill, REFILL, and RELEASE. Fill establishes a new context and loads the first K/V tile, REFILL retains the existing Query data and context configuration while replacing only the currently resident K/V, and RELEASE frees the context after reuse completes. Once a context is established, software obtains the operands required by subsequent RVV computation through view operations: a row view returns the contiguous feature vector of a selected Query, K, or V row, a column view fixes one feature dimension and forms data arranged along the token direction, and Panel4 forms the column views corresponding to four adjacent feature dimensions in a single request. After these operands are written to the VRF, QK, Softmax, and PV continue to execute using standard RVV instructions; AKV therefore changes only K/V residency and operand supply rather than taking over Attention arithmetic. When the head dimension, K/V sequence length, or the number of Queries sharing the same K/V exceeds the range of a single execution, the runtime applies segmented scheduling along the feature dimension, partitions the K/V sequence into consecutive tiles along the token dimension, or groups Queries, respectively; Softmax state across K/V tiles and scheduling across segments and Query groups remain under software control. 

C. Runtime Composition and Fallback 

QBS and AKV target quantized projection and K/V operand supply for Attention, respectively, and operate together with standard RVV to form the Transformer execution path. Q/K/V projections, output projections, and feed-forward matrix multi-plications that satisfy the interface constraints can be mapped to QBS; after K/V cache writes complete and the AKV interface constraints are satisfied, AKV provides locally resident data and the required views for subsequent Attention computation, while the remaining operations continue to execute on RVV. Before dispatch, the runtime selects the specialized or RVV path according to constraints including quantization format, data layout, tensor shape, and data type, and directly uses the existing RVV implementation when the interface constraints are not satisfied. IV. M ICROARCHITECTURE 

A. Shared Execution, Dependencies, and State Visibility 

Fig. 2 presents the overall microarchitecture of QBS and AKV and their shared integration with the existing vector execution path. QBS, AKV, and ordinary vector memory oper-ations share the VLSU address-translation path, PMA checks, AXI interface, and Lane result path, while the Sequencer con-tinues to use existing instruction identifiers to track destination-register dependencies and completion state. QBS commands and AKV context operations wait for older vector operations to complete and for relevant ordinary memory transactions to drain before entering execution, and use the shared VLSU resources under mutually exclusive arbitration, ensuring that read responses, fault information, and returned results remain associated with the active execution request. QBS result-accumulation state belongs only to the current command and is independent of the activation snapshot reused across commands; AKV K/V state may persist across multi-ple view instructions, while each view instruction retains its own destination register, dependencies, and completion state. Both mechanisms update architecturally visible state only after successful execution: QBS commits its final results after the associated memory accesses and computation complete, while AKV marks a context valid only after it has been completely filled without a fault. During reuse, QBS activation snapshots and AKV contexts do not reaccess the corresponding source addresses or automatically track changes to source memory, so software must rebuild or release the corresponding state when the source data change or reuse ends. 

B. QBS Native-Block Execution and Ordered Accumulation 

As shown in Fig. 3(a), the QBS datapath performs native-block fetch, format decoding, integer computation, FP32 ac-cumulation, and result commit. A tagged read path accom-modates different native-block sizes and weight layouts; re-turned data are byte-aligned and reassembled into complete native quantized blocks before entering the decode path se-lected by the corresponding profile. The weight layout may be transformed during model loading; for example, the four-row block-interleaved layout (R4) interleaves native blocks at the same K position from four output rows without changing their internal block encoding, thereby aligning the weight-read order with multi-output computation. Decoded data enter four parallel integer compute clusters, each containing eight signed INT8 ×INT8 multipliers, for 32 integer multiplications in parallel. For M = 1 , 2, 4, each cluster serves one, two, or four activation rows, respectively; the Wide mode for M = 5 –

8 reuses the same weight tile and processes the activation rows in two waves. Integer dot-product results are reduced within the corresponding subgroups and then corrected and scaled according to the active profile to form FP32 block-level updates. Different profiles primarily differ in format decoding and block-level update rules, while sharing the integer dot-product, reduction, and FP32 accumulation resources. Block-level updates enter the FP32 accumulation path, where tags track in-flight updates and prevent conflicts on the same accumulation state. Updates for different outputs may proceed in an interleaved manner, while updates to the same output always preserve native K-block order. The current implemen-tation provides 128 command-local FP32 accumulation states, allowing an entire M × N result tile to remain inside QBS throughout reduction along K and avoiding repeated VRF writeback after each native block; after the reduction completes, the final FP32 results are written to the destination vector-register group. 

C. AKV Banked Storage and Multi-View Operand Supply 

As shown in Fig. 3(b), AKV distributes the resident K/V tile across eight single-port banks according to the token index, with token t mapped to bank t mod 8 and K and V occupying separate logical regions while preserving the external row-major layout. This organization directly supports reading K/V rows by token and forming K column views by feature dimen-sion. For a K-column access, the hardware fixes one feature dimension; in each round, the eight banks read the storage words corresponding to the current 8-token group and extract the F16 element at the same position, so a column containing 

Tvalid valid tokens requires only ⌈Tvalid /8⌉ bank-read rounds. Panel4 further extracts the F16 fields corresponding to four adjacent feature dimensions within the same read round and forms four column views without requiring additional SRAM read ports. K/V fill, row reads, and column-view generation share the same single-port banks under mutually exclusive arbitration; validity bits mask invalid tokens in tail tiles. V. E VALUATION 

A. Evaluation Methodology and Baselines 

We use a functionally validated Ara implementation [24] with known implementation issues corrected as the baseline. All experiments use a four-lane configuration with VLEN=1024, ELEN=64, and a 128-bit AXI interface. Operator-level tests use cycle-accurate RTL simulation with tensors captured from real-model execution. Paired experiments use identical inputs and numerical acceptance criteria, with data layouts organized according to the corresponding kernels. We report execution cycles, AXI response bytes on the shared vector port, and retired vector instruction counts, and use internal hardware counters to analyze the major execution constraints. For projection, the baseline uses format-specific multi-output RVV kernels optimized on Ara. Compute includes dynamic ac-tivation quantization and matrix computation, whereas Matmul 

denotes the matrix-computation phase; static weight prepacking is performed during model loading. For Attention, we compare Direct RVV, GQA-aware Tiled RVV, and AKV. Tiled RVV already applies software tiling and K/V reuse across queries, so its comparison with AKV measures the incremental benefit of local K/V residency and operand-view supply. Model-level functional runs validate runtime dispatch and fallback across different models and Attention configurations. PPA evaluation uses the same architectural parameters and implementation constraints to quantify the implementation cost and efficiency of the proposed design. 

B. Quantized Projection Performance and Reuse 

Fig. 4(a) compares projection performance across represen-tative block-quantized formats. QBS achieves geometric-mean speedups of 35.68 × and 51.34 × for Compute and Matmul, respectively, showing that organizing format processing, inte-ger computation, and result updates as native-block execution substantially reduces quantized-projection overhead. Fig. 4(c) further supports this result from both data movement and instruction execution: all evaluated formats return fewer AXI bytes than the RVV baseline, while the number of retired vector instructions falls to only 0.42%–0.56% of the baseline. The performance gain therefore reflects not only a more efficient compute path, but also reduced data movement and explicit RVV instruction overhead. Fig. 5(a) further exposes format-dependent execution be-havior. Q3 K–Q6 K are primarily dominated by dot-product execution, with more pronounced weight-supply stalls in Q5 K and Q6 K. In contrast, the more frequent result updates of Q8 0 make FP32 update overhead more prominent. Fig. 5(b) and Fig. 6(a) examine activation and weight reuse, respectively. Reusing quantized activations reduces the total cycles of three identical projections by 47.6%, while Wide-M shares weights across activation rows and reduces the input payload by 33.2% for equal work. The former avoids repeated activation quantiza-tion, whereas the latter reduces redundant weight reads, further reducing projection overhead from activation preparation and weight supply. 

C. Attention Performance and K/V Supply 

Fig. 4(b) compares Attention latency during Decode. Relative to Tiled RVV, which already exploits GQA-aware tiling and K/V reuse across queries, AKV achieves a 1.45 × geometric-mean speedup. As the KV length increases from 16 to 256, the speedup rises from 1.22 × to 1.60 ×. Since the software baseline already explicitly exploits K/V sharing, the remaining gain shows that K/V organization and delivery still constitute significant data-supply overhead, whose impact becomes more pronounced as the context grows. Fig. 5(c) further decomposes this gain. With the effective K/V payload unchanged, two-query sharing combined with Panel4 reduces column-view commands and local replay by 81.7% and 30.4%, respectively, while reducing execution cycles by 14.5%. The improvement therefore primarily comes from more efficient organization and supply of resident K/V rather than from reducing the effective data volume or the Attention computation itself. D. Model Applicability and Runtime Validation 

This section evaluates design applicability through cross-configuration RTL tests and model-level functional runs. Be-yond the D128/GQA configurations used in the main evalua-tion, Refact D64/MQA32 [25] and Gemma 3 D256/GQA4 [26] reuse the existing K/V residency and view-supply structures and achieve 2.04 × and 2.55 × speedups over Direct RVV, respectively. Model-level functional runs cover Qwen2.5 [27], Qwen3 [28], Refact, and Gemma 3; all cases execute native QBS commands and validate AKV runtime dispatch and fall-back, and all pass functional checks. These results show that different model configurations can be accommodated through software scheduling without changing the core hardware struc-tures, thereby supporting multiple model configurations while preserving compatibility with the existing execution path.

VI. C ONCLUSION 

This paper proposes QBS and AKV to exploit state and reuse relationships that persist across instructions in LLM inference. QBS unifies native-block format processing, block traversal, and ordered FP32 accumulation, while AKV reduces operand-organization overhead through local K/V residency and multi-view supply while preserving the existing RVV arithmetic path. RTL evaluation shows that the two mechanisms reduce quantized-projection and K/V-supply overhead while improving throughput per area and energy efficiency. Validation across multiple quantization formats and model-specific Attention organizations further shows that the design accommodates diverse LLM inference configurations while retaining a unified hardware structure and RVV programmability.
