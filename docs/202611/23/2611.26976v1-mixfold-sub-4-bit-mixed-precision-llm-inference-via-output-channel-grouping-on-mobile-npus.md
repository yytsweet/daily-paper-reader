## 摘要
亚 4 比特量化使移动设备能够运行更大的 LLM，但其内存节省并不总能转化为移动 NPU 上更快的解码。其矩阵单元仅支持少数原生整数数据类型，而在向量单元上转换不支持的权重格式可能会抵消更少比特带来的收益。混合精度还面临额外约束：每个矩阵单元瓦片只能使用一种数据类型。MixFold 使用原生整数运算执行 3 比特和完全对称的 2 比特权重，在解码过程中无需将权重扩展为更宽的数据类型。随后，MixFold 将数据类型分配给与矩阵单元瓦片对齐的输出通道组，从而在不干扰矩阵单元执行的情况下实现比按层更细粒度的分配。我们在 Snapdragon 8 Elite Gen 5 的高通 Hexagon NPU 上将 MixFold 与 llama.cpp 的 Hexagon 后端进行比较。在 Qwen3 系列模型上，在每权重比特数匹配的情况下，MixFold 达到与 llama.cpp 的亚 4 比特格式相当或更高的精度，同时解码速度快 1.16–1.41 倍，每焦耳生成的 token 数多 1.5–4.3 倍。

## Abstract
Sub-4-bit quantization allows mobile devices to run larger LLMs, but its memory savings do not always translate into faster decoding on mobile NPUs. Their matrix units support only a few native integer datatypes, and converting unsupported weight formats on the vector unit can erase the gains from fewer bits. Mixed precision faces an additional constraint: each matrix-unit tile uses one datatype. MixFold executes 3-bit and perfectly symmetric 2-bit weights using native integer operations without expanding the weights to wider datatypes during decoding. MixFold then assigns datatypes to output-channel groups aligned with the matrix-unit tiles, enabling finer-than-layer assignment without disrupting matrix-unit execution. We compare MixFold with llama.cpp Hexagon backend on the Qualcomm Hexagon NPU of a Snapdragon 8 Elite Gen 5. Across the Qwen3 model family, MixFold achieves comparable or higher accuracy than llama.cpp's sub-4-bit formats at matched bits per weight, while decoding 1.16-1.41 times faster and generating 1.5-4.3 times more tokens per joule.

# MixFold 论文结构化总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：亚 4 比特（sub-4-bit，平均每权重低于 4 比特）量化可让移动设备容纳更大的 LLM，从而支撑涉及通讯录、照片、日历、消息等个人数据的端侧 AI 场景。
- **核心矛盾**：在移动 NPU 上，亚 4 比特的内存节省并不总能转化为解码加速。原因在于：
  - NPU 矩阵单元（如 Hexagon 的 HMX）硬件上只原生支持少数几种整型数据类型；3-bit 权重与“完美对称 2-bit 网格”（W2-SEQ）均为**非原生格式**。
  - 非原生格式需先在向量单元（HVX）上转换为更宽类型（如 W4/FP16）再送入矩阵单元，而移动 NPU 单条 HVX 线程吞吐比矩阵单元低 2–3 个数量级，转换代价在解码（M=1，权重复用极少）时无法摊销，反而抵消少比特收益。
- **混合精度的额外约束**：每个矩阵单元 tile 只能使用一种数据类型，因此逐通道混合精度会在 tile 内混入不同位宽而破坏原生布局；重排通道又需额外还原开销。
- **两个硬性要求**：① 混合中的每种数据类型都必须原生执行；② 每个权重 tile 只能持有一种位宽。现有方法（llama.cpp 运行时转换、T-MAN 用 LUT 但让矩阵单元空转、逐层 MP 忽略层内敏感性差异、逐通道 MP 破坏 tile 布局）无法同时满足。
- **整体含义**：论文提出 MixFold，目标是在不转换权重、不让矩阵单元空闲的前提下，让 sub-4-bit 与混合精度在移动 NPU 上真正兑现“字节减少即延迟下降”的承诺。

## 2. 方法论

### 2.1 核心思想
- **不转换权重，而是“折叠”修正项**：将非原生格式的额外计算折叠到**成本随激活规模（而非权重规模）增长**的操作数上，使权重保持原生低比特布局直接送入 HMX。
- **混合精度对齐硬件 tile**：以与矩阵单元 tile 对齐的**输出通道组**（T=32 个连续输出通道）为粒度分配数据类型，实现“细于层级、又不破坏 tile 原生布局”的分配。

### 2.2 关键技术细节

- **W2-SEQ 的行和折叠（Row-Sum Fold）**
  - 离线编码：W2-SEQ 可写为 `W̃2 = 2W2 + 1`，以原生有符号 W2 打包存储，保留原 SEQ 缩放与输入偏置。
  - 运行时：`Σ Xq·W̃2 = 2P2 + Rm`，其中 `Rm = Σ Xq` 为激活行和（仅依赖输入行，不依赖输出通道）。
  - **Bias-fold（M=1）**：只有一行，R1 可并入每通道输入偏置，`Y = Requant(P2; 2α, (ebin − R1)/2)`，每次调用 HVX 只做一次行归约。
  - **Accumulator-fold（2≤M≤32）**：将 `Rm/2 = Rc/2 + Lm` 拆分，Rc 并入偏置，Lm 通过向 Xq 追加 S 个“修正列”Λ、向权重追加 +1 列，由 HMX 累加器直接吸收，最终单次 Requant 输出；仅奇偶取整带来半个累加单元的近似。
  - 相比“输出修正形式”（需额外 HVX 输出遍历且可能因重复饱和损失精度），两种折叠均在 Requant 前修正、只饱和一次。

- **W3 的位平面折叠（Bit-Plane Fold）**
  - 表示：`W3 = 2W2 + W1`，W2 为有符号 2-bit 平面、W1 为无符号 1-bit 平面；背靠背存放恰好 3 bit/权重（N、K 为 32 倍数时共 3NK/8 字节）。
  - **Activation-fold**：由线性性 `P3 = 2P2 + P1`，把因子 2 折入激活（`⌊Xq/2⌋`），令两平面共享同一累加器，避免两次 Requant 与重复饱和；以 `b̂in,3` 补偿丢弃激活 LSB 的期望误差，单次输出饱和。
  - **并行执行**：W1 平面为二值，M=1 时用 HVX 以 4 激活一组预计算 2^4 子集和 LUT（每通道 K 次 MAC 降为 K/4 次查表），与 HMX 的 W2 平面 MMA 并行；M 较大时改用 **HMX-only** 变体（2MNK MACs）。

- **流水线与路径选择**
  - DMA 最多预取 3 个 chunk 到 VTCM 环形槽，HMX 对就绪 chunk 做 MMA，HVX 负责激活布局、输出物化与折叠中间项。
  - 折叠路径把权重转换移出关键路径，使内核从 HVX-bound 转为 weight-stream-bound；W3 延迟 36.2→18.4 µs、W2-SEQ 20.1→12.2 µs。
  - 运行时按 M 选择路径：M≤32 用折叠路径（M=1 用 bias-fold / HVX 辅助 activation-fold，2≤M≤32 用 accumulator-fold / HMX-only），M≥64 转用 expand 路径（转换成本被更多行摊薄）。

- **输出通道组混合精度与配置搜索**
  - 粒度：每组 T=32 个连续输出通道，整组共享一种格式（W2-SEQ / W3 / W4），组内所有 K 方向 tile 共享每通道缩放。
  - 成本估计：基于二阶（Hessian）近似，用对角经验 Fisher 替代 Hessian（仿 SqueezeLLM）：`εg,p = Σ E[(∂L/∂W)²]·(ΔW^p)²`，同时刻画权重敏感度与量化扰动幅度。
  - 分配：在目标 BPW 预算下求解 0-1 整数线性规划（ILP），最小化加性二阶损失代理，每组恰选一种格式。

## 6. 主要结论与发现

- **折叠路径使非原生格式接近原生效率**：W2-SEQ fold 与原生 W2 解码延迟几乎持平（除 0.6B 外有效带宽差 <1%）；W3 fold 延迟为原生 W4 的 0.77–0.82×，接近字节比例理想值；expand 路径则慢 1.41–1.63×。
- **折叠路径在 M≤32 内均优于 expand**；M≥64 后 expand 因转换被摊薄而反超，运行时据此做形状相关路径选择。
- **混合精度内核延迟随 BPW 线性缩放**，含非原生格式的 {W2-SEQ,W3,W4} 调色板与纯原生 {W2,W4} 缩放性相当；能耗也随 BPW 缩放，但因折叠额外计算，W2-SEQ/W3 相对 W2–W4 插值线存在偏移。
- **更细粒度 + 更丰富调色板提升精度–BPW 帕累托前沿**：输出通道组分配一致优于逐层分配（低 BPW 时增益更大）；用 W2-SEQ 替代 W2、再加入 W3 均进一步提升同 BPW 精度。

- **端到端对比 llama.cpp**：同 BPW 下解码快 1.16–1.41×，每焦耳 token 多 1.5–4.3×，精度上与同 BPW 的 k-quant 基线大体相当或更优（尤其在低 BPW 档位，MixFold 的 PPL 与零样本平均分优势更明显）；预填充阶段因受算力约束、权重带宽收益有限，加速幅度小于解码阶段。
- **加速来源可归因**：端到端收益主要来自解码阶段权重流带宽的节省（折叠路径把内核从 HVX-bound 转为 weight-stream-bound），而非算力提升；因此模型越大、解码越受带宽限制，收益越显著（0.6B 上收益最小，8B 上最大）。
- **混合精度的收益是“结构性”的**：在相同平均 BPW 下，混合精度配置优于任何单一均匀位宽，说明层内（输出通道组级）敏感度差异确实存在且可被利用；而该收益只有在“每种格式都原生执行、且不破坏 tile 布局”的前提下才能转化为实际延迟下降——这正是 MixFold 的核心论点。
- **调色板与粒度的正交性**：更细粒度（输出通道组 vs. 逐层）与更丰富调色板（加入 W2-SEQ、W3）对精度–BPW 前沿的改进近似可叠加，二者不互相替代。
- **消融结论**：bias-fold 与 accumulator-fold 分别在其适用 M 区间内优于 expand 路径；HVX-assisted 的 W3 变体在 M=1 时优于 HMX-only，而 HMX-only 在 M 增大后反超；多 HVX 线程数增加对折叠路径收益有限（因其已非 HVX-bound），这从侧面印证了瓶颈转移的判断。

- **端到端覆盖有限**：仅在 M=1 单流解码下做端到端验证，未覆盖投机解码、多序列并发（continuous batching）等 M>1 场景；虽然内核层面扫描到 M=512 并给出路径选择策略，但缺少这些场景下的端到端吞吐与能耗数据。

## 8. 启示与可复现性评价

- **方法论启示**：论文的核心思路——把非原生格式的修正项“折叠”到规模随激活（而非权重）增长的操作数上——是一种具有一般性的软硬件协同设计范式：当硬件只原生支持少数数据类型时，与其在关键路径上做格式转换，不如重新代数化量化表示，使低比特权重可直接进入矩阵单元。该思路可推广到其他“非原生位宽 + 权重带宽受限”的推理场景。
- **系统启示**：论文强调“内存节省 ≠ 延迟下降”，并通过内核级的 bound 分析（HVX-bound → weight-stream-bound）给出可验证的归因，这种“先定位瓶颈、再设计算法”的论证方式比单纯的端到端加速数字更有说服力。
- **可复现性**：
  - **较好**：给出了硬件平台型号、模型清单、量化配置、BPW 统计口径、热控测量协议（5 次取中位数、启动温度阈值 10°C）、对比基线版本号（llama.cpp b11444）与 GGUF 来源，实验设置描述较为具体。
  - **不足**：未披露训练/量化所用 GPU 资源；自建运行时与 AIMET 模拟的具体配置细节有限；T-MAN 复现依赖作者自行实现；代码与模型是否开源未在正文中明确说明。整体属于“设置可理解、但完全独立复现门槛较高”的类型。

## 9. 总体评价

MixFold 针对“移动 NPU 上 sub-4-bit 量化难以兑现延迟收益”这一真实且被广泛忽视的矛盾，给出了一个论证链条完整、工程落地性强的解决方案：以行和折叠（W2-SEQ）与位平面折叠（W3）消除关键路径上的格式转换，以输出通道组粒度对齐硬件 tile 实现可执行的混合精度，并以形状相关的路径选择覆盖 M 的整个取值区间。其贡献不在于提出新的量化算法，而在于**打通了量化表示与 NPU 数据通路之间的“最后一公里”**，并用同 BPW 配对比较、内核级归因消融和能耗测量支撑了主张。主要不足在于端到端验证局限于单流解码、精度主结果依赖模拟、以及离线搜索成本与代码开源的披露不足。总体而言，这是一篇问题定义清晰、系统与算法结合紧密、实验维度较丰富的高质量软硬件协同推理优化工作。
