## 摘要
向量量化（VQ）通过将一组数值编码为紧凑的码本索引，实现大语言模型（LLM）的超低位宽压缩。然而，为进行计算而重建这些数值需要频繁的码本查找，这与传统LLM加速器的数据流相冲突，并限制了VQ压缩带来的性能收益。因此，先前工作转向VQ专用加速器设计，但这些设计要么带来大量额外硬件开销，要么仅支持有限的推理场景。在本工作中，我们认为现有的基于脉动阵列的LLM加速器已具备高效VQ推理所需的关键硬件资源，但缺乏有效利用这些资源的机制。为弥合这一差距，我们提出VQACC，一种架构增强方案，它联合重新设计现有操作数缓冲区的访问逻辑和数据映射，以复用其存储与端口资源进行码本查找，从而将反量化无缝集成到常规的操作数寻址数据流中。评估表明，VQACC相比EVA基线实现2.63倍加速，额外硬件仅占计算阵列面积的0.17%。

## Abstract
Vector quantization (VQ) enables ultra-low-bit compression of large language models (LLMs) by encoding groups of values as compact codebook indexes. However, reconstructing these values for computation requires frequent codebook lookups, which conflict with the dataflows of conventional LLM accelerators and limit the performance gains from VQ compression. Consequently, prior work has resorted to VQ-specific accelerator designs, which either incur substantial additional hardware overhead or support only a limited range of inference scenarios. In this work, we argue that existing systolic-array-based LLM accelerators already possess the essential hardware resources for efficient VQ inference, but lack the mechanisms to effectively exploit them. To bridge this gap, we present VQACC, an architectural enhancement that jointly redesigns the existing operand buffer's access logic and data mapping to reuse its storage and port resources for codebook lookups, seamlessly integrating dequantization into the normal operand-addressing dataflow. Evaluation shows that VQACC achieves a 2.63$\times$ speedup over the EVA baseline, with additional hardware occupying only 0.17\% of the compute array's area.

# 论文总结：Exploring the Potential of Ultra-Low-Bit Inference on LLM Accelerators（VQACC）

## 1. 核心问题与研究动机

- **背景**：LLM 推理受内存容量与带宽瓶颈制约，权重与 KV Cache 需反复读取；量化是缓解该瓶颈的关键手段。
- **VQ 的优势**：向量量化（VQ）将一组 d 个数值联合编码为码本索引，有效位宽可低至 4-bit/2-bit/1-bit，且在同位宽下精度优于逐元素量化（Fig. 2），是超低位宽推理的有力候选。
- **核心矛盾**：VQ 反量化需按索引频繁查表（codebook lookup），与常规 LLM 加速器的操作数供给数据流冲突，导致严重的片上数据搬移与 bank 冲突——在某些场景下 VQ 甚至比 FP16 还慢（Fig. 2(c)）。
- **已有方案的不足**：
  - **Vortex**：专用反量化流水线 + 多 bank 码本缓冲 + 查表暂存缓冲，硬件开销大，且暂存缓冲容量限制了最大 tile。
  - **EVA**：将查表移到输出侧（输出缓冲当部分和表），但仅支持权重 VQ、不支持 KV Cache VQ，收益集中在小 batch 解码，无法支持 prefill。
- **本文主张**：现有脉动阵列（SA）加速器的操作数缓冲寻址天然兼容码本查找，其容量与端口也足以支撑典型码本的并行无冲突查找——缺的只是"有效利用这些资源的机制"。

## 2. 方法论（VQACC）

### 核心思想
不新增独立反量化阶段，而是**联合重设计现有操作数缓冲（WB）的访问逻辑与数据映射**，把码本查找折叠进正常的操作数寻址数据流，以极小硬件代价实现 VQ 反量化。

### 四项关键技术（Fig. 3 中 ①–④）

- **① 码本-索引映射（Codebook-Index Mapping）**
  - 以 64 KiB WB（32 个 16-bit 双端口 bank）为例，将每个 32 KiB 乒乓半区拆为 16 KiB 索引区 + 16 KiB 码本区。
  - 索引区：16 KiB 索引在 d=2 时可解码为 64 KiB FP16，足以容纳原本 32 KiB 半区的任何未量化 tile。
  - 码本区：可放 32/d 个码本（单个 256 项 FP16 码本占 512d B），恰好填满 16 KiB。
  - 每个码本**分散在 d 个相邻 bank**，每 bank 存一个元素位置，一次访问 d 个 bank 即取出完整向量，无 bank 冲突；32 个 bank 形成 32/d 个并行查找组。

- **② 索引地址生成器与端口复用（Index Addr. Gen + Port Multiplexing）**
  - 32 个 bank 各取一个端口作为**查找结果读出**（每周期 32 个 FP16，正好匹配 SA 消耗速率）。
  - 取 8 个相邻 bank 组成"索引窗口"，提供 128-bit 索引读入；128-bit 字含 16 个 8-bit 索引，即使 d=2 也能覆盖全部 32/d 个码本。
  - 用 4:1 MUX 在 32 个 bank 间滑动该窗口；地址生成器把 128-bit 索引字转换为 32 个 bank 地址，下一周期驱动查找读端口。
  - 剩余 24 个 bank 提供写端口（48 B/cycle），在乒乓调度下写入下一 tile 的索引与码本。
  - 每周期仅消耗 32/d 字节索引，片上流量比 FP16 权重少 2d 倍。

- **③ 移位布局单元（Shift Layout Unit）**
  - 问题：SA 按对角波前供给操作数（第 t 周期第 c 列取 reduction 位置 k=t−c），而 VQ 向量沿 reduction 维分布、查表结果并排返回，需转置。
  - 方案：**基于反向放置的移位转置**——reduction 位置 k 存入 bank b = B−1−(k mod B)；码本内向量逆序存放，跨码本顺序也逆序。
  - 推导得目标 bank 到目标列的距离恒为 c−b ≡ t+1 (mod B)，与列无关；故每周期对所有 bank 输出做 (t+1) mod B 的循环右移即可（一个 B-lane 16-bit 旋转器）。
  - 对沿输出维布局的 VQ 算法（如 value cache 的 CQ），无需转置，零移位自然顺序存放。
  - 该单元不增加任何周期或流水级，对 SA 而言操作数供给与常规数据流完全一致。

- **④ 码本驻留数据流（Codebook-Stationary Dataflow）**
  - 按码本共享分区（Fig. 6 的四种划分：Kmax/Nmax/CK/CN）调整 tile 尺寸：
    - 当 C_D > B 时，T'_D = min(T_D, C_D)，避免 tile 跨越码本边界；
    - 当 C_D ≤ B 时，T'_D = n·C_D（n 取满足 nC_D ≤ B 的最大正整数），使 tile 尽量大。
  - 保持原有操作数与结果驻留性，仅重排 tile 遍历顺序，优先走完当前码本区域，使码本在 WB 中长期驻留，减少重载。

## 6. 主要结论与发现

- **性能**：VQACC 平均较 Full FP16、VPU Dequant、EVA-OL32、Vortex-IL 分别加速 **1.79×、1.71×、2.63×、1.10×**；在所有模型/VQ 组合/解码配置下均为最快（除小 batch 下 EVA 略优）。
- **关键洞察**：仅优化查找操作本身不够（Full FP16 与 VPU Dequant 仅差几个百分点）；VQ 压缩掉大部分 DRAM 访问后，瓶颈转向**片上执行时间与反量化产生的片上流量**。
- **EVA 的局限被量化验证**：仅 batch ≤8 时最优，随 batch 增大延迟上升，多 batch 下甚至慢于 FP16，且不支持 KV VQ 与 prefill。
- **Vortex 的局限**：staging 缓冲容量限制最大 tile，导致 SA 排空更频繁；VQACC 因反量化完全在既有数据通路内，某些场景可用更大 tile、获得更高 SA 利用率。
- **面积**：VQACC 新增逻辑仅 **3,785 µm²**，占 SA 面积 **0.17%**，比 EVA-OL32 小 7.0×、比 Vortex-IL 小 125.0×（且 Vortex 未公开微架构细节，实际开销更大）。
- **能耗**：解码每步动态能耗最低（1.300 J，对比 FP16 的 3.201 J、VPU 的 1.394 J、EVA 的 1.871 J、Vortex 的 1.365 J）。
- **Prefill**：至少不慢于 FP16，短上下文（32 token）时快 53%，随上下文增长趋平。
- **KV 长度**：优势随长度增大而更明显但趋于平台（KV2 在 32K 时稳定在 0.75×），原因是 attention 的码本共享分区限制了 tile 尺寸，SA 排空周期成为瓶颈。
- **码本驻留数据流**：attention 中相比码本无关基线降低 5.4–5.8× 延迟、5.3–6.1× 能耗；FFN 中延迟收益小但码本加载少 8×、能耗降 29%。

## 7. 优点

- **思路新颖且务实**："不造新硬件，而是复用已有资源"——把反量化重新表述为操作数寻址问题，避免专用流水线的面积与容量代价。
- **硬件开销极低**：0.17% SA 面积、零额外流水级、对 SA 完全透明，工程可落地性强。
- **通用性好**：同时支持权重 VQ 与 KV Cache VQ、解码与 prefill、各种 batch 规模，突破了 EVA 的场景限制。
- **反向放置 + 循环移位转置**设计巧妙：把布局对齐折叠进供给过程，用标准旋转器实现，无额外延迟。
- **码本驻留数据流**针对真实 VQ 算法的码本分区特性做 tile 重排，属于软硬协同的细节优化。
- **实验对照公平**：特意把 VPU 基线增强到同等查找带宽，从而干净地隔离出"片上流量"这一关键变量；对 Vortex 仅计缓冲面积也做了诚实说明。

## 9. 启示与可拓展方向

- **“反量化即寻址”的范式价值**：本文最重要的贡献不只是某个具体电路，而是把量化反量化问题重新表述为**操作数供给与地址映射问题**。这一视角可迁移到其他“查表型”算子——如混合专家（MoE）的专家权重索引、嵌入表查找、稀疏注意力的索引聚集等，均可尝试复用现有缓冲的寻址通路而非新增专用单元。
- **软硬协同的 tile 划分**：码本驻留数据流说明，VQ 算法的“码本共享分区”这一算法层属性可直接转化为硬件层的数据流约束。反过来，这也提示 VQ 算法设计者：码本共享粒度（C_D 与 bank 数 B 的关系）应当作为与精度并列的一等设计变量。
- **可进一步探索的方向**：
  - 将方案扩展到 **prefill 与 decode 混合的连续批处理（continuous batching）** 场景，验证码本驻留与乒乓调度在动态 batch 下的鲁棒性；
  - 结合 **1-bit/二值化 + VQ 的混合精度分层策略**，让不同层选用不同 d，检验映射方案的灵活性；
  - 在 **FPGA 原型或 RTL-to-GDS 流程**上验证时序收敛与端口时序，尤其是 32 bank 同时读出 + 4:1 MUX 滑窗的布线拥塞；
  - 与 **稀疏化、KV Cache 驱逐/压缩**等正交技术叠加，评估瓶颈是否再次转移。

## 10. 总体评价

本文是一篇**问题识别精准、方案轻量、工程可信度高**的体系结构论文。其核心洞见——超低位宽 VQ 的真正障碍不是查表本身，而是查表引入的片上数据搬移与既有数据流的错配——被实验清晰地量化验证（FP16 与“理想化 VPU 反量化”仅差几个百分点，而与真实可用方案差距达 1.7–2.6×）。方案以 0.17% 的 SA 面积、零额外流水级的代价，同时覆盖权重与 KV Cache、decode 与 prefill，显著优于 Vortex 与 EVA 两类代表性工作，并诚实说明了对比基线中的信息不对称。

主要短板在于**评估方法的成熟度**：全部结论建立在周期级模拟与 RTL 综合之上，缺少硅后或 FPGA 验证；精度结论为引用而非复现，端到端“精度—性能—能耗”的联合评估缺位；除码本驻留数据流外，其余三项关键设计缺少逐项消融。因此，本文更适合被视为**一个强有力且可落地的设计论点 + 充分的模拟证据**，而非已完成全流程验证的最终方案。对于从事 LLM 推理加速器与量化部署的研究者与工程师，本文的“复用既有寻址资源”思路与“码本驻留 tile 重排”细节均具有直接的参考价值。
