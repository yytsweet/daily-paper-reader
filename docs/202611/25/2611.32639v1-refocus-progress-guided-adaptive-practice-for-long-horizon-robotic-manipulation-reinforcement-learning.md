## 摘要
在线强化学习（RL）使视觉-语言-动作策略能够通过与环境交互而改进。然而，在长时程操作中，稀疏的成功/失败反馈几乎无法提供策略在何处遇到瓶颈的信息。此外，重复的完整任务 rollout 也使得这些瓶颈分析不足且练习不充分。为此，我们提出 ReFocus，一种进度引导的多轮 RL 框架，它在全局 RL 与局部 RL 之间交替，以识别任务特定瓶颈并为其分配额外练习。具体而言，在全局 RL 期间，我们将每个任务分解为子任务的有向无环图（DAG）。然后，利用基于 DAG 的进度奖励同时进行策略训练和瓶颈诊断。基于识别出的瓶颈，ReFocus 选择自适应练习窗口，定义从入口阶段到目标阶段的任务片段。它在局部 RL 期间为这些片段分配额外交互，同时更新整个策略。之后，它评估策略执行完整任务的效果，以进行下一轮 RL，从而形成全局 RL 与局部 RL 之间的迭代。在 LIBERO-Long 和 RoboCasa365 上的实验表明，ReFocus 分别达到 97.8% 和 51.3% 的成功率，而 π_{0.5} 基线为 90.6% 和 39.3%。此外，我们在三个长时程任务上评估了真实世界适配。在 BreadBaker 上，ReFocus 达到 95% 的成功率，而 π_{0.5} 为 30%。项目页面：https://refocus-robotics.github.io。

## Abstract
Online reinforcement learning (RL) enables vision-language-action policies to improve through environmental interaction. However, in long-horizon manipulation, sparse success/failure feedback provides little information about where policies encounter bottlenecks. Moreover, repeated full-task rollouts also leave these bottlenecks weakly analyzed and insufficiently practiced. To this end, we introduce ReFocus, a progress-guided multi-round RL framework that alternates between Global and Local RL to identify task-specific bottlenecks and allocate additional practice to them. Specifically, during Global RL, we decompose each task into a Directed Acyclic Graph (DAG) of subtasks. Then a DAG-based Progress Reward is leveraged for both policy training and bottleneck diagnosis. Based on the identified bottlenecks, ReFocus selects Adaptive Practice Windows, defining task segments from an entry stage to a target stage. It allocates additional interaction to these segments during Local RL while updating the entire policy. After that, it evaluates the policy to perform the full task for the next round of RL, forming an iteration between Global and Local RL. Experiments on LIBERO-Long and RoboCasa365 show that ReFocus achieves success rates of 97.8% and 51.3%, respectively, compared with 90.6% and 39.3% for the $π_{0.5}$ baseline. Furthermore, we evaluate a real-world adaptation on three long-horizon tasks. On BreadBaker, ReFocus achieves 95% success, compared with 30% for the $π_{0.5}$. ## 1. 核心问题与研究动机

- **背景**：视觉-语言-动作（VLA）策略经模仿学习（SFT）初始化后，在部署时面对自身累积偏差容易失败；在线强化学习（RL）可通过环境交互继续改进，但现有在线 RL 多依赖**完整任务 rollout 的稀疏二值终端奖励**。
- **核心痛点一：奖励信号贫乏且不平衡**。不同失败 episode（如“碗搬运失败”与“放上架子失败”）完成的进度不同，却得到相同的 0 奖励；即便引入子任务进度奖励，若按子任务均匀分配，**分解粒度越细的阶段会获得越多权重**，导致奖励分配失衡（Reward Imbalance）。
- **核心痛点二：瓶颈练习不足**。在固定交互预算下，真正限制整体成功率的阶段得不到充分练习；且“早期失败”会阻断对后续瓶颈的尝试（例如每次尝试放架子都要先重新抓取搬运），也缺乏对失败原因的深入分析。
- **整体含义**：论文提出一个**进度引导的多轮 RL 框架 ReFocus**，用子任务 DAG 提供稠密进度反馈并诊断瓶颈，再把额外交互预算定向投放到瓶颈片段，从而在长时程操作中更高效地提升成功率。

## 2. 方法论

### 2.1 核心思想
- 将训练组织为 **Global RL（全任务）↔ Local RL（瓶颈片段）** 的交替多轮迭代，二者优化**同一个共享 VLA 策略**（π0.5 + PPO）。
- 用 LLM 驱动的 **Scheduler** 在轮次之间完成：瓶颈诊断 → 选择自适应练习窗口 → 指定里程碑奖励 → 依据历史决定保留/修改/跳过窗口。

### 2.2 关键技术细节

**(a) 任务 DAG 与阶段平衡进度奖励（Global RL）**
- 每个任务表示为有向无环图 $G=(V,E)$，节点为可验证子任务，边为前置依赖；共享前置条件的子任务构成一个“阶段”，阶段内可任意顺序完成，但需全部完成后下一阶段才可计分。
- **阶段平衡分配**：总进度奖励预算固定为 2，S 个阶段每阶段 $B_s=2/S$，阶段内 $n_s$ 个子任务各得 $B_s/n_s$。这样**子任务划分粒度不会改变阶段总权重**。
- 进度奖励：$r^{prog}_k=\sum_{s=1}^{S}\frac{B_s}{n_s}\sum_{v\in V_s} z_{v,k}$（$z_{v,k}$ 为子任务首次有效完成指示）。
- 总奖励：$r^G_k = r^{prog}_k + \lambda_{succ} z^{succ}_k$（式 2）。

**(b) 瓶颈诊断**
- Global RL 中每 5 次更新做一次验证 rollout，记录进度序列 $p_{0:K}$、观测序列 $o_{0:K}$ 与任务结果。
- Scheduler 对比失败 rollout 的进度序列，找出**最早反复停滞的阶段**，并结合 4×4 时间线拼图（含左右视角与腕部相机）描述停滞动作与证据，证据不足时显式报告不确定性。

**(c) 自适应练习窗口（Local RL）**
- 窗口 $w=(s_{entry}, s_{target}, B)$，配合里程碑集合 $M$ 与可恢复的训练入口库 $\mathcal{B}$：$(w,\mathcal{B},M)=S(D,H;E)$（式 3）。
- **三种 rollout 模式**（按概率 $p_m$ 采样）：
  - *Normal*：从恢复的中间状态出发，专注瓶颈片段；
  - *Prefix*：从正常任务起点出发推进到窗口目标；
  - *Suffix*：从恢复状态出发继续完成剩余全任务。
  三者把“瓶颈练习”与“前序继承状态”“后续任务要求”连接起来。
- **里程碑奖励**：在窗口内用更细粒度里程碑奖励替代目标子任务奖励（避免重复计分）：
  $r^L_k = r^{prog}_k - \frac{B_s}{n_s}z_{v,k} + \sum_{j\in M_i}\eta_j z^{mile}_{j,k} + \lambda_{succ}z^{succ}_k$，其中 $\sum_j \eta_j = B_s/n_s$（式 4）。

**(d) 历史缓冲与交替优化**
- History Buffer $H$ 记录：诊断出的瓶颈、所选窗口与里程碑、交互成本、练习前后全任务成功率变化；后续轮次据此**保留、修改或跳过**窗口。
- 每轮 = 25 次 Global RL 更新 + 25 次 Local RL 更新，共 3 轮（150 次 PPO 迭代），之后做全任务评估。
- 策略优化用 PPO + Flow-SDE：对 flow-matching 动作块，随机选一个去噪步用 Euler–Maruyama 采样构造高斯转移，比率 $\rho_k(\theta)=\exp(\ell_k(\theta)-\ell_k(\theta_{old}))$（式 9），奖励经 GAE 进入优势估计（式 10）。

### 2.3 算法流程（Algorithm 1 概要）
1. Scheduler 由任务集合生成各任务 DAG；
2. 每轮：Global RL 采样全任务轨迹、计算 $r^G$、PPO 更新、周期性验证收集 $D$；
3. Scheduler 依据 $D,H$ 选出窗口与里程碑；
4. Local RL 按三种模式采样、计算 $r^L$、PPO 更新并统计交互成本；
5. 轮末全任务评估，更新 History Buffer，进入下一轮。

- 多种子鲁棒性：LIBERO-Long 3 个训练种子、RoboCasa365 3 个评估种子；
- 真实世界 3 任务 × 3 方法 × 3 运行 × 20 试次；
- 机制分析：奖励分配、练习分配、GAE 信用分配、逐轮成功率曲线、

续上文列表，机制分析还包括逐轮成功率曲线、Scheduler 决策的可读性示例，以及附录中对失败阶段的统计归类（400 条 rollout、228 次失败）。整体看，实验覆盖了仿真、真实机器人和机制分析，横向对比基线较全，消融实验也较系统，能够支撑“进度奖励与瓶颈定向练习互补”这一核心论点。

**充分性评价**：
- **较强之处**：仿真与真机均验证；对“奖励怎么给”（阶段平衡、里程碑）与“练哪里”（窗口、rollout 模式、History Buffer）两个维度分别做了拆解，且消融并非只做单点开关，而是包含 4 种 rollout 模式组合与 4 种窗口选择变体，能较好排除“收益仅来自额外交互量”这一替代解释（因为所有方法共享相同交互预算）。
- **相对薄弱之处**：① 主实验主要围绕 π0.5 一个底座，缺少跨 VLA 架构（如不同动作头、不同预训练数据）的迁移验证；② 任务规模集中在 10–16 个任务、3 个真机任务，未覆盖更高物体数或更长时程（>5 阶段）的极限情形；③ 对 DAG 质量本身的敏感性讨论有限——DAG 由 LLM 生成，若分解错误或阶段划分不当，阶段平衡奖励的“权重不变性”优势可能被削弱；④ 真机部分每任务 50 条演示 + 50 次自主 rollout，样本量偏小，且仅 3 个任务，统计效力有限；⑤ 训练超参（3 轮 × 25+25 更新、每 5 次更新一次验证）为固定设定，未见对轮数、窗口长度、Global/Local 预算配比的敏感性扫描。

## 6. 主要结果与发现

- **仿真主结果**：在 LIBERO-Long 与 RoboCasa365 Composite-Seen 上，ReFocus 在 Overall 成功率上优于 SFT 初始化策略、Sparse-RL、SimpleVLA-RL、PolicyTrim 与 StructRL；且优势随 horizon 变长而更明显，说明方法收益主要来自长时程任务中“早期失败阻断后续瓶颈”这一结构性问题，而不仅仅是奖励变稠密。
- **消融结论**：
  - 进度奖励与练习窗口**单独使用均有提升，组合后收益最大**，支持二者互补而非冗余（表 2）。
  - Local RL 的三种 rollout 模式中，Normal + Prefix + Suffix 的组合最佳，说明“继承前序状态”与“回到全任务要求”二者缺一不可；仅做瓶颈片段练习会丢失上下文（表 3）。
  - 奖励反馈形式上，子任务级进度 + 里程碑细化的效果优于纯二值或纯子任务级（表 4）。
  - 窗口选择上，基于诊断的自适应窗口优于固定窗口或随机窗口；History Buffer 的保留/修改/跳过机制带来额外增益（表 13），说明“跨轮记忆”确实避免了重复练习同一非瓶颈阶段。
- **Scheduler 分析**：不同 LLM 作为 Scheduler 均可工作，性能随模型能力提升而提升，但成本差异显著（$1.28 / $0.51 / $0.05 量级），提示该框架存在“性能—成本”可调的设计空间（表 14）。
- **机制分析**：奖励分配分析显示阶段平衡使各阶段累计奖励权重与分解粒度解耦；练习分配分析显示额外交互预算确实向诊断出的瓶颈阶段倾斜；信用分配可视化显示瓶颈片段内动作获得了更高的优势估计，符合设计意图。
- **真机结果**：在 StackBowl / PickFruit / BreadBaker 三个任务上，ReFocus（及其 RECAP 适配版）相对 SFT 与 RECAP 基线取得更高成功率，验证了方法在真实人形机器人、真实视觉噪声与人类演示数据条件下的可迁移性。

## 7. 方法优势

- **问题定位准确**：把“稀疏终端奖励”与“瓶颈练习不足”明确区分为两个独立痛点，并分别给出对应机制，而非笼统地“加稠密奖励”。
- **奖励设计有原则**：阶段平衡分配使总奖励预算固定为 2，且阶段权重与子任务分解粒度无关，缓解了细粒度阶段被过度加权的问题；里程碑奖励通过扣除原子任务奖励避免重复计分，设计上较为自洽。
- **训练组织巧妙**：Global/Local 交替 + 共享同一策略，避免了单独训练“瓶颈专家”带来的分布偏移；三种 rollout 模式有效缓解了从中间状态恢复时的上下文缺失。
- **LLM 只做调度、不做控制**：Scheduler 输出的是窗口、里程碑与保留/跳过决策，不直接产生动作，降低了 LLM 幻觉对策略安全的直接影响，也使失败可归因。
- **工程可落地**：给出并行环境数、PPO 迭代数、Scheduler API 成本，便于复现与成本估算。

## 8. 局限与可质疑之处

- **对 DAG 与验证器的依赖**：子任务可验证性依赖外部检测器（成功判定），若检测噪声大，进度奖励会被污染；论文未充分报告检测器精度对结果的影响。
- **LLM 调度的一致性**：Scheduler 每 5 次更新读取一次验证数据并做诊断，其判断的稳定性（同一数据多次调用是否给出同一窗口）未见定量评估，仅给出定性示例与不确定性声明。
- **交互预算口径**：虽然声称与基线共享预算，但 Local RL 的中间状态恢复（从入口库 $\mathcal{B}$ 重置）在真实环境中可能需要额外的人工或脚本化重置成本，这一“隐性成本”未计入比较。
- **泛化性证据有限**：单底座、少任务、短真机试验，尚不足以说明方法在开放任务族上的普适性；DAG 由 LLM 自动生成，跨任务规模扩展时的生成质量与人工校验成本未讨论。
- **奖励塑形的理论保证缺失**：阶段平衡与里程碑奖励属于人工设计，未讨论其是否保持最优策略不变（potential-based 形式的讨论缺失），存在引入次优行为的风险。

## 9. 结论与启示

ReFocus 的核心贡献在于把“稠密进度反馈”与“瓶颈定向练习”统一进一个多轮 RL 框架：用阶段平衡的 DAG 进度奖励解决“奖励贫乏且不平衡”，用 LLM 诊断 + 自适应练习窗口 + 三种 rollout 模式解决“瓶颈练习不足”，并用 History Buffer 实现跨轮的练习决策复用。实验上，仿真两个长时程 benchmark 与真机三任务的结果，配合较系统的消融与机制分析，基本支撑了其设计主张。

对后续工作的启示是：长时程 VLA 的在线 RL 瓶颈可能不在算法本身，而在**奖励的分配结构**与**交互预算的投放位置**；将 LLM 限制在“调度与诊断”角色、把控制权留给策略，是一种兼顾可解释性与安全性的可行折中。未来值得探索的方向包括：DAG 与验证器的联合学习或自动校验、跨底座迁移、以及把“隐性重置成本”纳入统一预算框架的评测协议。
