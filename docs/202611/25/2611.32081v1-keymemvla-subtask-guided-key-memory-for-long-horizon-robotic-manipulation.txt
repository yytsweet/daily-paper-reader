Abstract
Memory-dependent long-horizon manipulation requires
vision-language-action (VLA) policies to infer task progress
and recall evidence absent from current observations. Un-
der a limited memory budget, the challenge is to retain
history that resolves stage ambiguity and supports subse-
quent decisions. We present KeyMemVLA, a subtask-guided
key memory framework based on progress indication and
decision-evidence retention.
A two-level annotation pro-
cess selects subtasks satisfying either criterion and labels
their final frames as keyframes to supervise online memory
writes. A shared vision-language backbone jointly learns
subtask, action, and keyframe prediction. At inference, the
policy first predicts the current subtask from the instruction,
visual context, and memory, then uses this semantic condi-
tion to predict actions and future memory-write positions.
Actual observations are retained at the selected times dur-
ing execution. We introduce KMBench to evaluate active
memory retention for decisions across subtasks. Evalua-
tions on RMBench-M(n), RoboTwin-MeM, KMBench, and
real-world manipulation tasks show higher average success
rates than the compared baselines. Ablation studies and
representation analysis support the roles of key memory and
explicit task-progress semantics. These results highlight the
value of coupling sparse key memory with online progress
inference for history-dependent control.
1. Introduction
Vision-language-action (VLA) models transfer pretrained
visual and linguistic knowledge to robot control, enabling
general instruction following and manipulation [2, 14, 22,
38, 43]. History-dependent long-horizon manipulation ad-
ditionally requires information absent from the current ob-
servation. In Find Heaviest (Fig. 1(a)), a robot weighs
four boxes, returns each to its original position, and selects
the heaviest.
Similar workspace configurations recur af-
ter each measurement, while the scale readouts disappear.
The policy must distinguish which measurements have been
completed and recall the evidence needed for comparison.
These are two distinct demands on memory: inferring task
progress from similar observations and recovering historical
evidence to choose an action even when the stage is known.
Existing approaches encode history through observa-
tion sequences, hierarchical memories, or compact learned
states [10, 19, 28, 30, 42]. Visual-memory methods pre-
serve sampled video or selected perceptual evidence [24,
25, 33, 35, 37], while memory-based planners and uni-
fied VLAs use history for subtask reasoning [3, 21,
26].
Progress-aware retrieval, execution-state modeling,
and completion checks further connect memory to task
stages [4, 11, 17, 18, 39]. These advances expose a con-
sequential trade-off: extended histories increase processing
costs, while compression and sparse selection risk losing
brief cues needed later. Under a finite budget, retained ob-
servations should supply progress cues or decision evidence
beyond what the existing context provides. The challenge
we address is to make these task-dependent selection cri-
teria explicit and coordinate memory retention with stage
inference and action generation across subtasks.
We present KeyMemVLA, a subtask-guided key mem-
ory framework for history-dependent manipulation. Our in-
sight is that memory value depends on what a subtask es-
tablishes and what subsequent decisions require. We there-
fore select history by two criteria: indicating task progress
and preserving evidence required for current or subse-
quent decisions. These criteria guide a two-level annota-

2. Related Work
2.1. Memory-Augmented Robotic Manipulation
Memory-augmented policies differ in how they represent
and retain execution history. History-aware transformers
2


and recurrent policies encode observation–action sequences
or latent states [10, 16, 30, 32].
Hierarchical memory,
state-space models, and test-time fast-weight updates pro-
vide alternative mechanisms for maintaining long-term con-
text [19, 28, 42]. Visual memories retain feature banks,
compress past views into tokens, or preserve sampled video
histories [9, 25, 31, 35].
Sparse memory selects particular observations: KEMO
uses kinematic events and visual filtering [37], EventVLA
predicts future memory-write positions [33], and Keyframe-
Chaining VLA retrieves selected frames according to exe-
cution progress [4]. Other representations combine short-
term video with long-term text [29], integrate visual and
textual memory with control [21], or encode changes be-
tween visual states [20]. These approaches vary in temporal
coverage, retained perceptual detail, and the cost of main-
taining history.
2.2. Task Progress Modeling for Robot Control
Task-progress modeling distinguishes execution phases that
may share similar observations. Language-grounded plan-
ning and reasoning connect task semantics to control [12,
36]; memory-based planners additionally condition subtask
selection on execution history [3, 26].
Explicit progress
models use different state representations:
TaskAnchor
learns a stage coordinate, ChainVLA carries execution con-
text across policy queries, and TFP maintains a dynamically
updated progress belief [11, 17, 18].
Completion moni-
toring supports stage transitions: EventSync verifies sub-
goal completion before updating completed-subgoal his-
tory [39]. Stage inference estimates the current execution
phase, while completion verification establishes whether an
operation has finished and its completion can be recorded.
Mem-0 selects the next subtask using a separate planner
triggered by subtask completion [3], whereas our policy re-
estimates the current subtask at each decision cycle.
2.3. Benchmarks for Memory-Dependent Manipu-
lation
Memory-focused benchmarks characterize different histor-
ical dependencies. MemoryBench tests spatial and action-
history recall [9], while MIKASA-Robo evaluates object,
spatial, and sequential memory, as well as memory ca-
pacity [5].
RMBench organizes tasks by memory com-
plexity [3], and RoboMME distinguishes temporal, spa-
tial, object, and procedural memory [8].
Interaction-
centric suites examine transient evidence and historical se-
quences: RoboTwin-MeM focuses on evidence acquired
during interaction [33], while RoboMemArena covers com-
posite manipulation and reports both task success and stage-
level progress [15].
Diagnostic extensions control infor-
mation availability or interference: MIKASA-Robo-VLA
combines hidden-cue tasks with reactive controls [6], and
RoboMME-Interference inserts unrelated sessions into the
supplied history [23].
3. Method
3.1. Overview
We define key memory Mt as task-relevant information se-
lectively retained from execution history.
Selection fol-
lows two criteria.
Progress indication retains cues that
distinguish task stages with similar current observations.
Decision-evidence retention preserves information needed
for current or later decisions, even when the stage is known.
Let Ht denote the complete observation–action history
and g the task instruction. Following EventVLA’s visual
anchoring strategy [33], we group the initial observation,
K sampled recent observations, and the current observation
into visual anchors VAt = (o0, oτ1, . . . , oτK, ot), where
τ1 < · · · < τK < t. The initial frame provides a sta-
ble reference and recent frames capture local temporal con-
text, paralleling the functions of Mem-0’s anchor and slid-
ing memories [3]. In our implementation, current observa-
tions include all camera views, whereas historical anchors
and keyframes use only the main view. We aim to approxi-
mate the full-history optimal policy π⋆with a policy ¯π con-
ditioned on these anchors and key memory:

3.2. Subtask-Guided Key Memory Construction
We construct key memory at two levels: key-subtask se-
lection and keyframe extraction. A subtask is selected if
it satisfies at least one of the key memory selection cri-
teria in Sec. 3.1: it provides an important cue to overall
task progress, or it exposes evidence needed for current
or later decisions. In Find Heaviest, weighing a box
marks measurement progress and yields evidence for the
final comparison. Returning it can be omitted from key-
subtask selection because it adds neither necessary progress
information nor comparison evidence.
For each key subtask, only its last frame is labeled as a
keyframe. Where needed, subtask boundaries are refined so
that the final frame captures observable outcomes or tran-
sient evidence.
This frame marks a stage boundary and
often preserves object attributes, spatial relations, or mea-
surements needed later. For example, the keyframe selected

3.4. Online Inference
Each episode starts with an empty key memory M0. At each
decision cycle, inference uses the shared backbone in two
stages (Fig. 2(a)). First, SPH generates the current subtask
ˆℓt from Ct autoregressively. The predicted text is then fed
back as the subtask response to obtain Qt, from which the
action head and KPH predict At and pt, respectively.
Based on the predicted keyframe scores, we select the
highest-scoring future position in the action chunk if its
score exceeds the write threshold. When execution reaches
the selected time, the captured image is added to key mem-
ory for subsequent decisions. Temporal filtering suppresses
repeated writes from nearby keyframe predictions, keep-
ing the memory sparse. Images are retained chronologi-
cally, with the oldest entries evicted as needed to main-
tain C(Mt) ≤B. Current-subtask text is re-predicted at
each cycle, while visual key memory persists across cycles
(Fig. 2(c)). Write filtering and execution details are pro-
vided in Appendices A.4 and A.5.

Figure 3 illustrates eight bimanual tasks organized
around four memory requirements. Memory-guided selec-
tion retains evidence associated with objects or locations
for a later query. Multi-cue retention integrates associations
acquired across exploration and execution stages. Count-

visible in the current scene. Evidence reasoning combines
earlier measurements or test feedback to support calibration
and inference. For example, the evidence reasoning task

ferent battery pairs can be combined to identify the lowest-
charge battery. Policies must actively retain task-relevant
memory and its associations with objects, locations, or
events to support subsequent decisions. Task definitions and
memory requirements are detailed in Appendix B.1.

5. Conclusion
We introduced KeyMemVLA, a subtask-guided framework
that couples sparse key memory with online subtask pre-
diction, action generation, and learned memory updates
for long-horizon manipulation. We also introduced KM-
Bench to evaluate active memory retention for subsequent
decisions across diverse task interactions. Evaluations on
RMBench-M(n), RoboTwin-MeM, KMBench, and four
real-world tasks show higher average success than the com-
pared baselines. Ablations support keyframe memory and
the subtask prediction pipeline, while linear probes show
improved temporal-progress decodability from the back-
bone representations used for action prediction.

A.5. Real-World Inference and Execution
To implement online inference and memory updates on the
real robot, we use the StarVLA WebSocket interface [27]
to connect a policy server running on one NVIDIA A100
GPU with a client responsible for observation acquisition,
action execution, and memory management. Visual anchors
include the initial main-view image, historical main-view
images at offsets −30 and −15, and current images from
all three cameras; missing historical observations are re-
placed with the initial image. At each policy query, the
server first predicts the current subtask, followed by action
and keyframe prediction. As specified in Table 11, the pol-
icy predicts an action chunk of length 30, while the client
executes at most 16 actions from each chunk.

Scan and Route.
The robot registers three items and

Button Pair.
Each side of the workspace contains
three candidate buttons, exactly one of which activates a
light. The light turns off when the button is released. The
goal is to activate both lights simultaneously by pressing
the working button on each side. Demonstrations explore
the two sides and undergo resets before the final joint press,
requiring the working-button locations to be retained across
resets.
B.1.3. Counting Memory
Two-Bin Count.
The robot deposits a specified num-
ber of orange blocks into each of two bins. The left and right
target counts, each ranging from 1 to 3, are shown only in
the initial frame. Deposited blocks are removed from the
scene, while spare blocks are replenished on the table; the
visible supply therefore does not reveal how many blocks
each bin has received. A deposit is counted when a released
block enters a bin. The policy must track completed de-
posits separately for the two bins and leave surplus blocks
on the table.
Conveyor Color Count.
Blocks of the displayed
target color and distractor colors arrive in sequence. The
robot transfers them to an output conveyor in arrival order,
returning the operating arm home after each transfer. Only
completed exits of target-color blocks count toward the dis-
played target, which ranges from 2 to 5. Once this count is
reached, the robot must finish the current transfer and arm
return, then press the completion button without handling
another block. Because exited blocks disappear, the policy
must track target-color exits separately from the total num-
ber of transfers.

Frozen representations.
The probes assess the linear de-
codability of temporal progress from action-query represen-
tations on RoboTwin-MeM. We freeze the final full-policy
and w/o SPH checkpoints in evaluation mode, using paired
instructions, current and initial observations, recent history,
and fixed visible keyframes. Online memory writes are dis-
abled. The full policy first predicts the current subtask and
conditions its action-prediction pass on the predicted text;
w/o SPH uses its native prompt without subtask text. We
mean-pool the 50 action-query representations from each
model’s action-prediction pass into h, taking features from
the final decoder block before the final RMSNorm.

B.5. Key Memory Mode Details
The three modes use the same RoboTwin-MeM demon-
strations, backbone, objectives, visual anchors, SPH, and
KPH. Each is jointly trained on all eight tasks. Image stores
keyframe images, Text stores key-subtask descriptions, and
ImageAndText stores both (Appendix A.3).
Training uses annotated key-subtask endpoints and their
descriptions. At inference, the predicted current subtask is
bound to a proposed write time. An accepted event commits
the acquired image, the bound description, or both when ex-
ecution reaches that time. Image–text pairs share a times-
tamp and remain paired through eviction. Descriptions at
distinct events are retained even when identical.
Memory starts empty and retains at most five events in
acquisition order, evicting the oldest when full. All modes
use only events with t′ < t. Table 22 gives the per-task
results and equal-weight averages.
